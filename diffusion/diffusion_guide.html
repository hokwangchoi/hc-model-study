Diffusion Transformer (DiT)

The transformer backbone behind today's image and video generators (Stable Diffusion 3, FLUX, Sora-style video models). The same flow-matching recipe drives the action expert of VLAs like π0. GPU inference study guide with sampling math, architecture, and edge deployment notes.

The Core Idea: Iterative Denoising

A diffusion model generates samples by slowly removing noise from a random starting point. Training teaches a neural network to predict the noise that was added to real data at some timestep; sampling runs that network in reverse, step by step.

The key insight: if the model can predict noise accurately, subtracting a little at each step walks us from pure Gaussian noise back to a real sample. Training is MSE regression — stable and well-understood — which is a big part of why diffusion beat GANs.

1. Forward Process: Adding Noise Analytically

The forward process is fixed (not learned) and has a closed form. At timestep t, the noisy sample is:

# One-step reparameterization:
x_t = sqrt(ᾱ_t) * x_0 + sqrt(1 - ᾱ_t) * ε       # ε ~ N(0, I)

# Small t → x_t ≈ x_0 (almost clean)
# t = T   → x_t ≈ ε   (almost pure noise)
# ᾱ_t = (1 - β_1)(1 - β_2)…(1 - β_t), precomputed once from the β schedule

This is the magic: we can jump directly to any timestep without simulating the intermediate steps. One multiplication, one addition, one noise sample. It works because adding Gaussian noise t times in a row is the same as adding one Gaussian with the combined variance, and ᾱ_t keeps track of how much of the original signal is left.

Worked example (one pixel, DiT's linear schedule). Take a clean value x₀ = 0.8 and draw ε = −1.2.

t = 250: √ᾱ = 0.7221, √(1−ᾱ) = 0.6918 → x_t = 0.7221·0.8 + 0.6918·(−1.2) = −0.2525

t = 500: √ᾱ = 0.2789, √(1−ᾱ) = 0.9603 → x_t = 0.2789·0.8 + 0.9603·(−1.2) = −0.9292

The two coefficients always satisfy (√ᾱ)² + (√(1−ᾱ))² = 1, so x_t keeps unit variance when x₀ does. At t = 500 only ᾱ = 7.8% of the variance is signal (SNR = −10.7 dB). The network's job: given x_t = −0.9292 and t = 500, guess ε = −1.2.

1.1 The noise schedule

The sequence ᾱ_1, ..., ᾱ_T controls how fast noise is added. Common choices:

Cosine changes ᾱ slowly near both ends, so fewer steps are spent on nearly-clean or nearly-pure-noise inputs than with the linear schedule (try the widget above). Nichol & Dhariwal introduced it for small pixel-space images; DiT kept ADM's linear schedule, and so does our reference implementation.

Pitfall: the end of the schedule. A sampler predicts the clean sample as x̂₀ = (x_t − √(1−ᾱ_t)·ε̂) / √ᾱ_t, so an error δ in ε̂ becomes an error of δ·√((1−ᾱ_t)/ᾱ_t) in x̂₀. At t = 999 that factor is 157 for the linear schedule but about 20,000 for cosine (ᾱ ≈ 2.4×10⁻⁹). In a 50-step DDIM test with an exact ε-predictor for Gaussian toy data (target std 0.5), adding noise of std 0.01 to ε̂ left the linear-schedule samples at std ≈ 0.47, while the cosine-schedule samples blew up to std ≈ 3.1 (exercise 3 reproduces this). That is why diffusion.py defaults to DiT's linear schedule.

2. The DiT Architecture

DiT replaces the classic U-Net denoiser with a pure transformer. Benefits: simpler code, cleaner scaling (more params consistently help), reuses all the transformer infrastructure. Downside: no inductive bias from conv downsampling.

At the top level, DiT is a pretty standard transformer pipeline with one twist: conditioning (timestep + class) is broadcast to every block through AdaLN parameters, not concatenated into the token sequence the way text prompts are in an LLM.

Two things to notice:

  • The main tensor path is linear — patchify → tokens → L transformer blocks → final layer → unpatchify → ε̂. Shape goes [B, 4, 32, 32] → [B, N, d] (preserved through all blocks) → [B, 4, 32, 32]. Input and output shapes match exactly.
  • The conditioning vector c is a single [B, d] vector built once from (t, y), then broadcast to every DiT block AND the final layer. The blocks never see t or y directly — only c.

Zooming in on a single DiT block — this is where AdaLN-Zero conditioning actually does its work:

2.1 adaLN-Zero — the key contribution

The novel part of DiT is how it injects conditioning. DiT compared four options: appending t and y as extra tokens ("in-context"), cross-attention to them, adaptive LayerNorm (adaLN), and adaLN-Zero. adaLN-Zero won and is also the cheapest:

  1. The condition vector c = t_emb + y_emb goes through SiLU and one Linear that outputs 6·d numbers per sample.
  2. Those 6d values are split into (shift₁, scale₁, gate₁, shift₂, scale₂, gate₂) (called shift_attn … gate_mlp in the code), each of shape [B, d].
  3. Shift/scale modulate the LayerNorm output, which has no learnable γ/β of its own: x̂ * (1 + scale) + shift.
  4. The gate scales the sub-layer's output before it is added back: x = x + gate · sublayer(…).

Worked example (one channel of one token). LayerNorm gives x̂ = 0.8. For this sample's timestep the Linear outputs scale₁ = 0.5 and shift₁ = −0.1, so attention sees 0.8·(1 + 0.5) − 0.1 = 1.1. Say attention returns 0.4 for this channel and gate₁ = 0.25: the residual stream changes by 0.25·0.4 = +0.1. At initialization the Linear is all zeros, so scale = shift = gate = 0: attention sees 0.8 unchanged and the residual stream changes by 0·0.4 = 0.

The "Zero" in adaLN-Zero. The final Linear producing those 6d values is zero-initialized. At training start, all gates are 0, so every block is an identity function. The network begins as a no-op and only gradually learns to modulate. In the paper's ablation (DiT-XL/2, 400K training steps, FID-50K without guidance, lower is better): in-context 35.24, cross-attention 26.14, adaLN 25.21, adaLN-Zero 19.47, at about the same Gflops as plain adaLN.

How newer DiTs add text (as of Oct 2026). A class label is one vector, but a prompt is a sequence of tokens, so text-to-image and text-to-video DiTs keep adaLN-style modulation for the timestep and add a second path for the text tokens:

2.2 Patchify / Unpatchify

Same trick as ViT: a Conv2d with kernel=stride=patch_size splits the input into patches and projects them to hidden_dim in one kernel. At the end, unpatchify reshapes the per-patch output back to a spatial grid.

3. Sampling Strategies

Training uses T = 1000 timesteps. Sampling doesn't have to visit all of them. How few steps you can get away with depends on two separate choices: the sampler (same trained network, different update rule) and whether the network was distilled or trained for few-step generation. The chart below uses real numbers from one paper so the two samplers are directly comparable:

What to notice: with the same trained model, the deterministic DDIM sampler degrades gracefully as steps drop (4.04 → 4.67 FID from 1000 to 50 steps), while the stochastic DDPM sampler degrades much faster (FID 8.0 at 50 steps, 41 at 10). Both axes are logarithmic.

3.1 DDIM — the default

DDPM defines a Markov chain of 1000 small denoising steps, each adding fresh noise. DDIM keeps the same trained network but uses a deterministic update (it corresponds to integrating an ODE), which lets you jump over most timesteps:

# DDIM update (deterministic, σ=0)
x_0_pred = (x_t - sqrt(1 - ᾱ_t) * ε̂) / sqrt(ᾱ_t)           # 1. guess the clean sample
x_{t_next} = sqrt(ᾱ_{t_next}) * x_0_pred + sqrt(1 - ᾱ_{t_next}) * ε̂   # 2. re-noise it to the next (lower) level

# Subsample timesteps: instead of 999..0 use e.g. [999, 979, 959, ..., 19] (50 steps)

Worked example: one DDIM step with a perfect network. Continue the pixel from §1: at t = 500, x_t = −0.9292 (from x₀ = 0.8, ε = −1.2). Suppose ε̂ = −1.2 exactly.

x̂₀ = (−0.9292 − 0.9603·(−1.2)) / 0.2789 = 0.8000

x_250 = 0.7221·0.8000 + 0.6918·(−1.2) = −0.2525

That is exactly the value the forward process gave at t = 250: with a perfect ε̂, DDIM slides back along the same noise direction, so 2 steps or 50 land in the same place. With an imperfect ε̂ (off by 0.05) the guess becomes x̂₀ = 0.6279: the error is multiplied by √((1−ᾱ)/ᾱ) = 3.44 at t = 500. Fewer, larger steps give the network fewer chances to correct such errors, which is the real cost of skipping steps.

Same network, no retraining. In the DDIM paper (CIFAR-10), 50 DDIM steps reach FID 4.67, against 4.04 for 1000 DDIM steps and 3.17 for the original 1000-step DDPM sampler: close to full quality at 20× less compute. DDIM-style deterministic samplers, and higher-order ODE solvers such as DPM-Solver++ and UniPC, became the default way to sample ε-prediction models.

3.2 Flow matching — the modern alternative

Rather than predict noise ε̂, predict a velocity vector along a straight-line path from noise to data:

# Training (t ∈ [0, 1], continuous; t = 0 is noise, t = 1 is data):
x_t = (1 - t) * ε + t * x_0          # linear interpolation
target_v = x_0 - ε                         # constant velocity along the path
loss = MSE(model(x_t, t), target_v)

# Sampling: Euler integration of dx/dt = v
for i in range(num_steps):
    t = i / num_steps
    v = model(x, t)
    x = x + v * (1 / num_steps)

Intuition with a single data point. If the whole dataset were one point x₀, the best velocity at (x, t) is (x₀ − x)/(1 − t): it points straight at x₀. One Euler step from t = 0 with step size 1 gives x + (x₀ − x) = x₀ exactly. Real data has many points, so the learned field averages over all the straight lines that pass near x, and the trajectories bend. That is why practical samplers still take tens of steps.

Why flow matching is now the default for new models. The objective is simple (plain MSE on a velocity) and the training paths are straight, so the learned trajectories are straighter than DDPM's and a plain Euler solver works. The same DiT backbone serves both: only the loss and the sampler change. Stable Diffusion 3 and FLUX are rectified-flow transformers; FLUX.1 [dev]'s reference example uses 50 sampling steps (FLUX.2 [dev]'s card notes 28 as a good trade-off), and π0 (Module 8) uses 10 Euler steps for robot actions. Watch the direction convention: SD3/FLUX write x_t = (1−t)·x₀ + t·ε, so their t = 1 is noise and the velocity flips sign.

3.3 Few-step models (as of Oct 2026)

Below about 10 steps you need a network trained for it, usually distilled from a many-step teacher. The student is a different set of weights with the same DiT/U-Net architecture, so the inference engine does not change; only the loop gets shorter.

4. Classifier-Free Guidance (CFG)

To steer generation toward the condition without training a separate classifier, train one model on both conditional and unconditional examples: DiT's code replaces the class label with a learned "null" class 10% of the time. At inference, run the model twice per step and extrapolate away from the unconditional prediction:

Worked example (one number). ε̂_uncond = 0.10 and ε̂_cond = 0.30. With w = 4: ε̂ = 0.10 + 4·(0.30 − 0.10) = 0.90. w = 1 gives back ε̂_cond (0.30, no guidance), w = 0 gives the unconditional model (0.10), and w > 1 pushes past the conditional prediction, away from "generic image" towards "very much this class". The price is diversity: too large a w gives saturated, samey images.

The quality gain is large: DiT-XL/2 goes from FID 9.62 without guidance to 2.27 with w = 1.5. Ways to avoid paying 2× for it:

  • Guidance distillation: train a student that takes w as an extra input and reproduces the guided output in one forward pass (Meng et al., 2023). FLUX.1 [dev] and FLUX.2 [dev] are released this way: their guidance_scale is fed to the network, so each step is a single forward.
  • Guidance on part of the trajectory only: Kynkäänniemi et al. (2024) found guidance harmful at high noise and largely unnecessary at low noise, and apply it only in the middle interval, which improves FID and skips the second forward for the other steps.

5. Code Walkthrough

NoiseSchedule — the forward process ▼

Purpose: Precompute ᾱ_t from a β schedule (DiT's linear one by default, cosine optional), and provide the q_sample function that jumps directly to a noisy timestep.

class NoiseSchedule:
    def __init__(self, num_timesteps=1000, schedule="linear",
                 beta_start=1e-4, beta_end=0.02, s=0.008, max_beta=0.999):
        if schedule == "linear":                     # DDPM / ADM / DiT
            scale = 1000 / num_timesteps
            betas = torch.linspace(scale * beta_start, scale * beta_end, num_timesteps, dtype=torch.float64)
        else:                                         # "cosine": Nichol & Dhariwal 2021
            t = torch.arange(num_timesteps + 1, dtype=torch.float64) / num_timesteps
            f = torch.cos((t + s) / (1 + s) * math.pi / 2) ** 2
            alpha_bar = f / f[0]
            betas = torch.clamp(1 - alpha_bar[1:] / alpha_bar[:-1], max=max_beta)
        self.alphas_cumprod = torch.cumprod(1 - betas, dim=0).float()   # ᾱ, length T
        self.sqrt_alphas_cumprod = torch.sqrt(self.alphas_cumprod)
        self.sqrt_one_minus_alphas_cumprod = torch.sqrt(1. - self.alphas_cumprod)

    def q_sample(self, x_0, t, noise=None):
        # Forward diffusion: x_t = √ᾱ_t · x_0 + √(1-ᾱ_t) · ε, one step, no iteration
        if noise is None: noise = torch.randn_like(x_0)
        sqrt_a = self.sqrt_alphas_cumprod[t].view(-1, 1, 1, 1)
        sqrt_1ma = self.sqrt_one_minus_alphas_cumprod[t].view(-1, 1, 1, 1)
        return sqrt_a * x_0 + sqrt_1ma * noise, noise

Key point: at training time we never actually iterate forward — we pick a random t and jump there. The Markov chain interpretation is for the reverse process at sampling time.

TimestepEmbedding — turning scalar t into a vector ▼

Purpose: Convert an integer timestep into a hidden_dim vector the DiT blocks can condition on. Uses the same sinusoidal pattern as Transformer position embeddings, followed by a small MLP.

class TimestepEmbedding(nn.Module):
    def __init__(self, hidden_dim, frequency_embedding_dim=256):
        super().__init__()
        self.frequency_embedding_dim = frequency_embedding_dim
        self.mlp = nn.Sequential(
            nn.Linear(frequency_embedding_dim, hidden_dim),
            nn.SiLU(),
            nn.Linear(hidden_dim, hidden_dim),
        )

    @staticmethod
    def sinusoidal_embedding(t, dim, max_period=10000):
        half = dim // 2
        freqs = torch.exp(-math.log(max_period) * torch.arange(half) / half).to(t.device)
        args = t[:, None].float() * freqs[None]
        return torch.cat([torch.cos(args), torch.sin(args)], dim=-1)

    def forward(self, t):
        emb = self.sinusoidal_embedding(t, self.frequency_embedding_dim)
        return self.mlp(emb)                    # [B, hidden_dim]

The sinusoidal embedding gives the network a smooth, continuous representation of "how noisy is this?" — nearby timesteps get similar embeddings.

DiTBlock — transformer block with adaLN-Zero ▼

Purpose: The reusable building block. Same skeleton as a Transformer block (attn + MLP + residuals) but every LayerNorm is modulated by the condition vector, and residuals are gated.

def modulate(x, shift, scale):
    return x * (1 + scale.unsqueeze(1)) + shift.unsqueeze(1)

class DiTBlock(nn.Module):
    def __init__(self, hidden_dim, num_heads, mlp_ratio=4.0):
        super().__init__()
        # elementwise_affine=False — modulation replaces learnable γ,β
        self.norm1 = nn.LayerNorm(hidden_dim, elementwise_affine=False, eps=1e-6)
        self.attn = nn.MultiheadAttention(hidden_dim, num_heads, batch_first=True)
        self.norm2 = nn.LayerNorm(hidden_dim, elementwise_affine=False, eps=1e-6)
        mlp_hidden = int(hidden_dim * mlp_ratio)
        self.mlp = nn.Sequential(
            nn.Linear(hidden_dim, mlp_hidden),
            nn.GELU(approximate="tanh"),
            nn.Linear(mlp_hidden, hidden_dim),
        )
        # 6 modulation params per block: shift/scale/gate for both attn and mlp
        self.adaLN_modulation = nn.Sequential(
            nn.SiLU(),
            nn.Linear(hidden_dim, 6 * hidden_dim, bias=True),
        )
        # The "Zero" in adaLN-Zero
        nn.init.zeros_(self.adaLN_modulation[-1].weight)
        nn.init.zeros_(self.adaLN_modulation[-1].bias)

    def forward(self, x, c):
        shift_a, scale_a, gate_a, shift_m, scale_m, gate_m = \
            self.adaLN_modulation(c).chunk(6, dim=1)

        # Attention path with modulated LN + gated residual
        x_mod = modulate(self.norm1(x), shift_a, scale_a)
        x = x + gate_a.unsqueeze(1) * self.attn(x_mod, x_mod, x_mod, need_weights=False)[0]

        # MLP path, same pattern
        x_mod = modulate(self.norm2(x), shift_m, scale_m)
        x = x + gate_m.unsqueeze(1) * self.mlp(x_mod)
        return x

Why zero-init matters: with gates initialized to 0, every block starts as an identity function. Training begins from a well-behaved neutral state. In Peebles & Xie's ablation (DiT-XL/2, 400K steps) zero-initializing the modulation took FID from 25.21 (adaLN) to 19.47 (adaLN-Zero).

DiT — the full model ▼

Purpose: Tie everything together. Input is noisy data + timestep + optional class; output is predicted noise of the same shape as the input.

class DiT(nn.Module):
    # in __init__: fixed 2D sin-cos table, a buffer (saved, never trained)
    # self.register_buffer("pos_embed", get_2d_sincos_pos_embed(d, H // P).unsqueeze(0))

    def forward(self, x, t, y=None, train=False):
        x = self.patch_embed(x) + self.pos_embed          # [B, N, d]
        c = self.t_embedder(t)                            # [B, d]
        if y is not None and self.y_embedder is not None:
            c = c + self.y_embedder(y, train=train)       # add class cond
        for block in self.blocks:
            x = block(x, c)                               # [B, N, d]
        x = self.final_layer(x, c)                        # [B, N, P²·C_out]
        x = self.unpatchify(x)                            # [B, C_out, H, W]
        return x

The whole model is one function: takes a noisy input and returns something the same shape. What it means (noise prediction or velocity) is determined by the loss you trained with, not by the architecture.

DDIMSampler — the reverse process with CFG ▼

Purpose: Iterative denoising loop. Run DiT N times, each time moving a bit closer to the data distribution. Supports classifier-free guidance by batching conditional + unconditional into a single forward.

class DDIMSampler:
    @torch.no_grad()
    def sample(self, shape, y=None, guidance_scale=1.0, device="cpu"):
        B = shape[0]
        x = torch.randn(shape, device=device)
        use_cfg = guidance_scale > 1.0 and y is not None

        for i in range(self.num_steps):
            t, t_next = self.timesteps[i], self.timesteps[i + 1]
            t_batch = torch.full((B,), t, device=device, dtype=torch.long)

            if use_cfg:
                # Batch cond + uncond into 2B for a single forward
                x_cat = torch.cat([x, x], dim=0)
                y_null = torch.full_like(y, self.model.y_embedder.num_classes)
                y_cat = torch.cat([y, y_null], dim=0)
                t_cat = torch.cat([t_batch, t_batch], dim=0)
                eps = self.model(x_cat, t_cat, y_cat)
                eps_cond, eps_uncond = eps.chunk(2, dim=0)
                eps = eps_uncond + guidance_scale * (eps_cond - eps_uncond)
            else:
                eps = self.model(x, t_batch, y)

            # DDIM reverse step (deterministic, σ=0)
            α_t = self.schedule.alphas_cumprod[t].to(device)
            α_next = self.schedule.alphas_cumprod[t_next].to(device) if t_next > 0 \
                else torch.tensor(1.0, device=device)
            x_0_pred = (x - (1 - α_t).sqrt() * eps) / α_t.sqrt()
            x = α_next.sqrt() * x_0_pred + (1 - α_next).sqrt() * eps

        return x

7. Critical Optimizations for Inference

7.1 Step reduction — the single biggest lever ▼

Total cost is linear in the number of network evaluations. Going from 1000 DDPM steps to 50 DDIM steps is a 20× saving for a small quality loss (§3); distilled students go further, to 1–4 steps. Typical step counts, as of Oct 2026:

MethodTypical stepsTrade-offUse when
DDIM50Small quality loss vs 1000-step DDPM (FID 4.67 vs 3.17 on CIFAR-10)ε-prediction models, no retraining
DPM-Solver++ / UniPC10–20 (DPM-Solver++: 15–20 for guided sampling)Higher-order ODE solvers; same networkSame, when you need fewer steps
Flow matching (Euler-type ODE solver)28–50 (FLUX [dev] examples)Requires a flow-matching-trained modelNew training runs
Consistency / LCM2–4Requires distillationReal-time applications

DPM-Solver's title promises sampling "in around 10 steps"; how few steps are acceptable for your model and prompt is something to measure, not assume.

7.2 Guidance distillation — remove the 2× CFG cost ▼

CFG doubles per-step compute because you run conditional and unconditional passes. Meng et al. (2023) first train a single student that takes the guidance scale w as an input and matches the combined guided output, then progressively distill it to fewer steps; for latent models such as Stable Diffusion they report good images in 1–4 steps.

This is now common in released models: FLUX.1 [dev] and FLUX.2 [dev] are "trained using guidance distillation" (model cards), so the guidance value you pass is just another conditioning input and each step costs one forward. In the calculator above, that is "1 forward per step".

7.3 Latent diffusion — always use it, and count the decoder ▼

A 512×512 RGB image has 786,432 values; Stable Diffusion's VAE turns it into a 64×64×4 latent with 16,384 values: 64× fewer spatial positions (48× fewer numbers). With the same patch size the DiT then has 64× fewer tokens, so the linear layers do 64× less work and the N² attention term 4096× less.

# Training: encode once, diffuse in latent space
latent = vae.encode(image).latent_dist.sample()   # [B, 4, 64, 64] for a 512×512 image
x_t, noise = schedule.q_sample(latent, t)
pred_noise = dit(x_t, t, class_label)
loss = mse(pred_noise, noise)

# Sampling: diffuse in latent, decode at the end
latent = sampler.sample(shape=(1, 4, 64, 64), y=class_label)
image = vae.decode(latent).sample                 # [1, 3, 512, 512]

The decoder is not free. It runs once per image, but it is a big convolutional network. Counting it with PyTorch's FLOP counter on the SD/LDM f=8 decoder architecture (49.5M parameters) gives about 0.62 TFLOP for a 256×256 image and 2.5 TFLOP for 512×512 (2 FLOPs per multiply-add). That is 13.5 DiT-B/2 forward passes. With a 50-step sampler the decoder is a rounding error; with a 4-step distilled model it costs more than the whole denoising loop. On the edge, a lighter decoder can matter as much as fewer steps.

7.4 FlashAttention and SDPA ▼

DiT blocks are plain transformer blocks, so FlashAttention applies directly. For DiT-XL/2 at 256 tokens the attention matrix is small (256² × 16 heads × 2 bytes = 2 MiB per layer per sample) and the score FLOPs are only about 3.6% of a block, so the win is modest at 256×256. It grows quickly with resolution: at 1024 tokens the matrix is 16× larger, and video DiTs attend over tens of thousands of spatio-temporal tokens. PyTorch SDPA picks a fused kernel automatically where supported.

import torch.nn.functional as F
# Uses FlashAttention / memory-efficient kernels when the GPU, dtype and shapes allow
x = F.scaled_dot_product_attention(q, k, v)       # no causal mask for DiT
7.5 Static shape compilation (TensorRT) ▼

Unlike LLM decoding, a diffusion step has static shapes: fixed latent size, fixed token count, fixed batch (2 with CFG), and the same network is called every step. That makes it a good fit for an ahead-of-time TensorRT engine:

  • Build one engine per resolution and batch; no dynamic-shape profiles needed
  • Capture the step as a CUDA graph to remove per-kernel launch overhead
  • On Orin, dense INT8 peak is about 2× FP16 (33 TOPS vs 17 TFLOPS on Orin Nano Super), so INT8 or mixed INT8/FP16 can help if quality holds
  • Export the VAE decoder too: it can dominate few-step pipelines (7.3)

The calculator gives a lower bound (DiT-B/2, one forward: 46 GFLOPs ≈ 2.7 ms at the 17 TFLOPS FP16 peak). Compare it with what trtexec reports on your board to see the utilization you actually reach (exercise 6).

7.6 Other levers (as of Oct 2026) ▼
  • 4-bit weights and activations. SVDQuant (2024) moves weight outliers into a small high-precision low-rank branch and runs the rest in 4 bits, with the two branches fused into one kernel; on the 12B FLUX.1 models it reports 3.5× lower memory and a 3.0× speedup over 4-bit weight-only quantization on a 16 GB laptop RTX 4090.
  • Reuse work across steps. Consecutive steps see similar inputs, so training-free caching methods reuse earlier outputs. TeaCache (2024, video diffusion) estimates from the timestep-modulated inputs when the output will barely change and reuses the cached result then; it reports up to 4.41× speedup on Open-Sora-Plan with negligible quality loss.
  • Guidance only where it helps (§4): apply CFG in the middle noise interval and run one forward elsewhere.

Biggest take-away: a DiT step behaves like an LLM prefill, not like decode. Every linear layer multiplies all N tokens by the same weights, so FP16 arithmetic intensity is about N FLOPs per weight byte. 9. Connection to VLA (Flow Matching on DiT)

The same recipe (a transformer trained with flow matching to denoise a continuous tensor) generates robot actions in vision-language-action models such as π0, covered in Module 8:

Going from "flow-matching transformer for images" to "flow-matching expert for robot actions" changes three things: the shape of the tensor being denoised (an action chunk instead of a latent image), where the condition comes from (the VLM's tokens, read through attention in every layer, instead of a class or prompt), and how the timestep enters (π0 uses an MLP on the action tokens; many image DiTs use adaLN). 11. Recap, Self-check & Exercises

Key takeaways

  • Training is regression: noise a sample to a random t in one line (x_t = √ᾱ_t·x₀ + √(1−ᾱ_t)·ε) and teach the network to predict ε (or a velocity).
  • DiT = ViT-style patchify + transformer blocks + unpatchify. The output has the input's shape; what it means (ε or velocity) is set by the loss.
  • adaLN-Zero turns (t, class) into per-channel shift/scale/gate vectors; zero-initializing them makes every block start as the identity (FID 19.47 vs 25.21 for plain adaLN in the paper's ablation).
  • Cost = network evaluations × FLOPs per evaluation. Samplers (DDIM, DPM-Solver++), flow matching and distillation attack the first factor: 1000 → 50 → 28 → 1–4.
  • CFG doubles the evaluations; guidance distillation (FLUX [dev]) or guiding only part of the trajectory removes most of that.
  • A DiT step is like an LLM prefill: ≈N FLOPs per weight byte, so it is compute-bound once N (tokens × batch) exceeds the GPU's ridge point (≈167 on Orin Nano Super in FP16).
  • The schedule's end matters: x̂₀ divides by √ᾱ_t, which magnifies ε̂ errors 157× at t = 999 on DiT's linear schedule and ~20,000× on cosine.
  • On the edge, count the VAE decoder: at 256×256 it costs about as much as 13 DiT-B/2 steps.

Self-check

Try each question before opening the answer.

1. Why can training jump straight to timestep t without simulating steps 1…t−1?

Answer

Each forward step adds independent Gaussian noise and scales the signal, and a sum of independent Gaussians is Gaussian. So q(x_t | x₀) has the closed form N(√ᾱ_t·x₀, (1−ᾱ_t)·I) with ᾱ_t = Π(1−β_s): one multiply-add and one noise sample.

2. With DiT's linear schedule, √ᾱ_500 = 0.2789. What fraction of x_500's variance is signal, and what is the SNR in dB?

Answer

ᾱ_500 = 0.2789² ≈ 0.078, so about 7.8% of the variance is signal. SNR = ᾱ/(1−ᾱ) ≈ 0.084, i.e. 10·log₁₀(0.084) ≈ −10.7 dB.

3. DiT-XL/2 on a 32×32 latent has N = 256 tokens. How many tokens with patch size 4, and roughly how do the FLOPs per forward change?

Answer

(32/4)² = 64 tokens. The linear layers scale with N (4× fewer) and attention with N² (16× fewer), so FLOPs drop about 4.1×: 237.2 → 58.1 GFLOPs per forward with compute_flops_per_step's formula. Parameters barely change.

4. ε̂_uncond = 0.10, ε̂_cond = 0.30. What does CFG give for w = 0, 1 and 4, and what does w = 4 cost?

Answer

0.10, 0.30 and 0.10 + 4·0.20 = 0.90. Any w ≠ 1 needs both predictions, so two forward passes per step (2× FLOPs), unless the model is guidance-distilled.

5. At initialization, what does a DiT block output for input x, and why is that useful?

Answer

Exactly x. The Linear that produces shift/scale/gate is zero-initialized, so both gates are 0 and both residual branches add 0. A deep stack of identities is a stable starting point; in the paper this initialization gave a clearly better FID than adaLN without it.

6. Why does DDIM with the cosine schedule become fragile if its first step is at t = 999?

Answer

x̂₀ = (x_t − √(1−ᾱ_t)·ε̂)/√ᾱ_t, so an ε̂ error δ becomes δ·√((1−ᾱ)/ᾱ) in x̂₀. Cosine (β capped at 0.999) has ᾱ_999 ≈ 2.4×10⁻⁹, a gain of ≈ 20,000; DiT's linear schedule has ᾱ_999 ≈ 4.0×10⁻⁵, a gain of ≈ 157.

7. On a Jetson Orin Nano Super, is a DiT-B/2 step at 256×256 compute-bound or memory-bound? Compare with an LLM decode step.

Answer

Ridge point = 17 TFLOPS / 102 GB/s ≈ 167 FLOP/byte. DiT-B/2: 46 GFLOPs over 261 MB of FP16 weights ≈ 176 FLOP/byte, just compute-bound (2.7 ms compute vs 2.6 ms to read the weights); with CFG it is 352 FLOP/byte. LLM decode at batch 1 does ≈1 FLOP/byte, deep in memory-bound territory.

8. A 4-step distilled DiT-B/2 makes 256×256 images on Orin. Where does the time go?

Answer

DiT: 4 × 46 GFLOPs = 184 GFLOPs ≈ 11 ms at peak. SD-style VAE decoder: ≈ 622 GFLOPs ≈ 37 ms. The decoder is ~3/4 of the work, so a lighter decoder now matters more than fewer steps.

9. With a single training point x₀, flow matching gives v(x, t) = (x₀ − x)/(1 − t). Show that one Euler step from t = 0 is exact. Why do real models still need many steps?

Answer

Start from noise z at t = 0 and take one step of size 1: z + 1·(x₀ − z)/(1 − 0) = x₀. With many data points, the learned velocity at (x, t) averages the straight lines towards all plausible x₀, so the field bends and a single large Euler step lands between modes (blurry samples).

10. π0 and an MMDiT image model both use flow matching. Name two architectural differences in how they are conditioned.

Answer

π0's action tokens attend to the VLM's tokens inside every layer (shared self-attention with separate expert weights), while MMDiT attends jointly over text and image tokens; and π0 mixes the timestep into the action tokens with an MLP, while DiT/MMDiT use adaLN-style modulation.

Hands-on exercises

All exercises use diffusion.py (CPU is fine). Use torch.float64 when comparing numbers.

1. Read the schedules (easy)

Print √ᾱ_t for both schedules and find where the SNR first drops below 0 dB.

lin, cos = NoiseSchedule(1000, "linear"), NoiseSchedule(1000, "cosine")

assert abs(lin.alphas_cumprod[999].item() - 4.036e-5) < 1e-7
assert round(lin.amplification(999)) == 157

2. adaLN-Zero is an identity at init (easy)

Build a tiny DiT, check that a block returns its input and the model returns zeros, then give the adaLN Linear random weights and watch both change.

m = DiT(input_size=8, patch_size=2, hidden_dim=64, depth=2, num_heads=4, num_classes=10).eval()

assert torch.equal(m.blocks[0](h, c), h) and (m(x, t, y) == 0).all()

3. Test DDIMSampler with an exact denoiser (medium)

For data x₀ ~ N(0, s²) the best possible ε-predictor is ε̂(x_t) = b/(a²s² + b²)·x_t with a = √ᾱ_t, b = √(1−ᾱ_t). Wrap it in an object with a __call__(x, t, y) and run the sampler with 50 steps on 4096 samples of shape (1, 2, 2), s = 0.5. Then add Gaussian noise of std 0.01 to ε̂ and compare schedules.

out = DDIMSampler(oracle, NoiseSchedule(1000, "linear"), 50).sample((4096, 1, 2, 2))
assert abs(out.std() - 0.5) < 0.05                  # ≈ 0.47
# with 0.01 noise on ε̂: linear stays ≈ 0.47, cosine grows to ≈ 3.1 (§1.1 pitfall)

4. Flow matching on 2-D toy data (medium)

Train a small MLP v_θ(x, t) (input: x and t, 2 hidden layers of 128, SiLU) with the loss of FlowMatchingTrainer.training_step on a mixture of two 2-D Gaussians at (±2, 0) with std 0.3 (Adam, lr 1e-3, 3000 steps of batch 512 take seconds on a CPU). Sample with 1, 4 and 20 Euler steps and count how many samples land between the modes.

# single-point sanity check first: with v = (x0 - x) / (1 - t), one Euler step is exact

assert between(sample(4000, steps=20)) < 0.05   # (our run: 1.00 / 0.14 / 0.016 for 1 / 4 / 20 steps)

5. Add η to DDIM (harder)

Generalize the update to DDIM's family: σ_t = η·√((1−ᾱ_next)/(1−ᾱ_t))·√(1−ᾱ_t/ᾱ_next) and x_next = √ᾱ_next·x̂₀ + √(1−ᾱ_next−σ_t²)·ε̂ + σ_t·z.
