Hands-on lab 03 of 10 · GPT + generation

A tiny GPT, sampling, and a KV cache that equals full recompute

Run a decoder-only transformer (GPT-2 layout) end to end: token ids in, next-token logits out. Then generate text with greedy decoding and top-k sampling, first by recomputing the whole sequence at every step, then with a KV cache. The cached version must produce the same logits and tokens. The model is untrained (random weights); correctness is what we check.

The maths, step by step

B batch, N tokens in this call, V vocab, d width, h heads, d_k = d / h. The code keeps nanoGPT's variable names (as build-llm does): T = N, T_past = N_past.

Forward pass

idx [B, N] (int64)
x = tok_emb[idx] + pos_emb[pos]                       [B, N, d]
    pos = start, start+1, ..., start+N-1  (start = number of cached tokens)
for each block (pre-norm, lab 02):
    x = x + Attn(LN1(x))
    x = x + MLP(LN2(x))
logits = LN_f(x) @ tok_emb^T                          [B, N, V]
    (the output head shares its weight with the token embedding: "tied")

Causal attention with a KV cache

q, k, v = split(x W_qkv^T + b)                         each [B, h, N, d_k]
k_all = cat(k_past, k), v_all = cat(v_past, v)          [B, h, N_past + N, d_k]
scores = q k_all^T / sqrt(d_k)                          [B, h, N, N_past + N]
mask: new token i sits at absolute position N_past + i and may see keys
      j <= N_past + i  →  causal_mask(N, N_past + N) from lab 01
y = softmax(scores) v_all  → merge heads → W_o        [B, N, d]
return y and the new cache (k_all, v_all)

Why the cache is exact: in a causal model the keys and values of token j depend only on tokens 0..j. Appending a token never changes them, so they can be computed once and reused. Each decode step then costs O(N) instead of re-running all N tokens through the model.

Decoding

greedy:  next = argmax(logits[:, -1])
top-k:   keep the k largest logits, divide by the temperature, softmax,
         sample one index from those k (temperature < 1 sharpens,
         > 1 flattens; k = 1 is greedy).

to write

Hint 1
one call; which dim holds the vocabulary?

sample_top_k(logits, k, temperature=1.0, generator=None)

to write

Top-k sampling. logits [B, V] → sampled token ids [B] (int64).

  1. keep the k largest logits of every row,
  2. divide them by temperature and softmax over those k,
  3. draw one of the k with torch.multinomial(..., generator=generator),
  4. map the drawn position (0..k-1) back to a vocabulary id.
Hint 1
torch.topk(logits, k, dim=-1) returns (values, indices), both [B, k].
Hint 2
probs = torch.softmax(values / temperature, dim=-1) choice = torch.multinomial(probs, 1, generator=generator) # [B, 1] in 0..k-1
Hint 3
return indices.gather(-1, choice).squeeze(-1)

4 generation, with and without a KV cache

generate(model, idx, max_new_tokens, use_cache=True, top_k=None, temperature=1.0, generator=None)

to write

Append max_new_tokens tokens to idx [B, T0]; returns [B, T0 + max_new_tokens].

top_k=None means greedy decoding; otherwise use sample_top_k(..., top_k, temperature, generator).

use_cache=False: every step runs the WHOLE sequence through the model

and uses the last position's logits.

use_cache=True: run the prompt once (the "prefill"), keep the returned

presents, then feed only the newly chosen token each step
together with the cache (the "decode" steps).
Hint 1
write a small helper pick(last_logits) that returns greedy_next(...) or sample_top_k(...). The last position's logits are logits[:, -1].
Hint 2 (no cache)
for _ in range(max_new_tokens): logits, _ = model(idx); idx = torch.cat([idx, pick(logits[:, -1])[:, None]], 1)
Hint 3 (cache)
logits, past = model(idx) once; then each step pick the token, append it to idx, and call logits, past = model(token[:, None], past). (You do not need the model call after the very last token.)
