2 Prefill: the whole prompt in one pass

Input: ids [B, N]. One forward pass over all N rows. Output: the KV cache of every layer, and the logits (one score per vocabulary token) of the last row, from which the first output token is sampled. Every weight GEMM (general matrix–matrix multiply) has M = B·N rows, so prefill is compute-bound (§2.6).

What to notice: one block is two read-modify-add branches on a residual stream that keeps the shape [B, N, d] through all L blocks. The bottom row opens the attention box: only the orange steps mix rows (tokens), and they carry the N² terms. Click any box to open its details below.

  • 1Read: a branch copies x off the stream and normalizes it (LN).
  • 2Compute: attention moves information between tokens; the FFN (d → 4d → d) transforms each token alone.
  • 3Add back: x ← x + f(LN(x)).

Each block opens to: the equation, a matrix picture with prefill and decode shapes, shapes in → out, FLOPs, bytes moved, a kernel note, the decode shapes (§3), a PyTorch line and the matching primer step. The red figures are the reference config at B = 1, N = 4,096, FP16, one layer, on AGX Orin. Bytes are unfused: the op reads its inputs from DRAM and writes its output once. The badge says which roof binds the op in prefill.

GPU kernel deep dive
  • A gather, not a GEMM. Each thread block copies one token's row of E (d·b bytes) and adds P's row. Nothing is reused, so time = bytes ÷ BW = b·(2·B·N·d + N·d) ÷ BW. Read more: GPU MODE lectures (lecture 4: compute and memory architecture).

GPU kernel deep dive
  • One row per warp. Each of the 32 lanes holds d/32 of the row's values in registers; μ and σ² come from warp-shuffle reductions, then the lane normalizes its values and writes them: one read, one write. Read more: Triton tutorial: layer norm.
  • Memory-bound by construction. ≈ 7 FLOPs per element against 2·b bytes (one read, one write): AI ≈ 7 / (2b) = 1.75 ≪ 208. Faster ALUs do nothing for it. Read more: NVIDIA, GPU performance background.
  • Fused add + norm. The residual add (block 10) and the next norm in one kernel: read X and Y, write X + Y (the stream) and its normalized copy. It saves one read of the stream, b·B·N·d bytes per pair, and one launch. Read more: cookbook card h, fusion and CUDA graphs.
  • Decode: launch-bound. d·b bytes in and out: at batch 1 the CPU cost of launching the kernel can exceed its GPU time. Read more: Horace He, Making deep learning go brrrr.

2.2 Attention, step by step

Multi-head attention in one line
MHA(X̂) = concat(head₁, …, head_h) · W_O, head_i = softmax(X̂WiQ (X̂WiK)ᵀ / √d_k + M) · X̂WiV

Read it aloud: each head i projects every row with its own [d × d_k] matrices, runs causal attention over the rows and returns [N, d_k]; the h results are glued side by side and mixed by W_O [h·d_k × d]. Blocks 3–9 compute exactly this for all heads at once. Toy numbers: primer steps 6–12.

Every matmul below, in one formula
C [M × P] = A [M × K] · B [K × P]
FLOPs = 2·M·K·P, bytes ≈ b·(M·K + K·P + M·P), AI = (2/b) / (1/M + 1/K + 1/P)

Read it aloud: each of the M·P outputs is a dot product of K pairs, one multiply and one add each. In FP16 (b = 2), AI = 1 / (1/M + 1/K + 1/P): the smallest of the three sizes sets it. (P is the output width, because N is the prompt length.)

  • Prefill weight GEMMs: M = B·N, and K, P are multiples of d. All three are large: AI in the thousands, compute-bound.
  • Decode: M = B, so AI ≈ B. Every weight read makes only B outputs: memory-bound.
  • Attention, per head: K or P is d_k, so AI < d_k = 128, under Orin's ridge of 208: memory-bound unless fused (FlashAttention).

GPU kernel deep dive
  • Tiling on Tensor Cores. A thread block owns one BM × BN output tile and loops over K = d in BK-wide slices staged in shared memory; warps issue Tensor Core MMAs (16 × 8 × 16 FP16 on Ampere, Orin's architecture). Each staged value is reused BN or BM times. Step through it in the CUTLASS deep dive below. Read more: Boehm, How to optimize a CUDA matmul; NVIDIA, Matrix multiplication background.
  • Prefill GEMM vs decode GEMV. AI = 1 / (1/M + 1/d + 1/(3d)). Prefill: M = B·N, compute-bound. Decode: M = B, so the same op becomes a GEMV that streams all 3d² weights for 6·B·d² FLOPs: AI ≈ B, paced by bandwidth. Read more: NVIDIA, Matrix multiplication background; cookbook §2, roofline.
  • One GEMM, and K, V written in place. Fusing Q, K and V reads X̂ once instead of three times (2·b·B·N·d bytes less per layer) and launches once. The epilogue can apply RoPE and write K and V straight into the cache layout. Read more: cookbook card h, fusion and CUDA graphs.
  • Split-K for small M. With M = B ≤ 8 there are only ⌈P/BN⌉ output tiles to hand out; split-K also cuts the K loop into s parts on s thread blocks and adds the s partial sums, so all 16 SMs of an AGX Orin stream weights. Read more: CUTLASS deep dive below; CUTLASS, Efficient GEMM in CUDA.
  • Weight-only INT4 GEMV. The kernel loads 4-bit weights and dequantizes them in registers just before the FMA: weight bytes drop from 2 to 0.5 per weight while the maths stays FP16, so decode AI ≈ 4·B. Decode speeds up; prefill barely changes. Read more: cookbook card c, quantization.

primer step 12

A common misreading: “the split cuts each token's d-vector into h slices, so each head sees only part of the token.” It does not. The reshape cuts Q's output columns, after a projection that reads all d inputs.

  1. The paper (Vaswani et al. 2017, §3.2.2) gives each head its own WiQ, WiK ∈ ℝd×d_k and WiV ∈ ℝd×d_v, and one W_O ∈ ℝh·d_v×d.
  2. Code stacks them side by side: W_Q = [W1Q | W2Q | … | WhQ], one [d × d] matrix.
  3. So the reshape is exact: columns i·d_k … (i+1)·d_k − 1 of X̂·W_Q are X̂·WiQ. Splitting the output columns does no arithmetic and loses nothing.
  4. Every head sees the whole token. Each column of Q is a dot product with all d numbers of the token: Q[n, c] = Σj=1…d X̂[n, j]·W_Q[j, c].
  5. Same parameters: h·d·d_k = d². The only difference is one large GEMM instead of h small ones, which keeps the GPU busy.
  6. Output side: concat(head₁ … head_h)·W_O = Σi head_i · W_O[rows i·d_k … (i+1)·d_k − 1]. W_O mixes all heads back into every output feature.

What to notice: the ✓ figure is the real computation with the primer's numbers (d = 4, h = 2, d_k = 2): column 0 of W_Q (outlined) runs over all four rows, so head 0's first number reads all four inputs. The ✗ figure is the lossy alternative: slicing x̂ before projecting is the same as zeroing the off-diagonal blocks of W_Q, so head 0 never sees 1.03 and −0.09. Transformers compute the ✓ figure.

Tiny example (x̂ of “sat” and W_Q from primer step 6): column 0 is −1.59·(−0.2) + 0.65·0.9 + 1.03·0.4 + (−0.09)·0.1 = 0.318 + 0.585 + 0.412 − 0.009 = 1.31, all four inputs. Head 0 = x̂·W_Q[:, 0:2] = [1.31, 0.51], head 1 = x̂·W_Q[:, 2:4] = [−0.54, −0.72], so Q[sat] = [1.31, 0.51, −0.54, −0.72]: the reshape only reads it as two rows. Slicing x̂ first would give [0.90, 0.35] and [0.07, −0.08]. Output side, with concat[sat] = [1.50, −0.08 | 0.34, −1.57] (step 12): [1.50, −0.08]·W_O[0:2] = [0.34, 0.65, 1.48, −0.24] plus [0.34, −1.57]·W_O[2:4] = [−0.48, −1.64, 0.82, 0.46] ≈ attn_out[sat] = [−0.15, −0.99, 2.29, 0.21] (the last digit differs by rounding). GPU kernel deep dive
  • A view is a stride change. Q.view(B, N, h, d_k).transpose(1, 2) only rewrites the strides: element (b, i, n, j) is still read at offset ((b·N + n)·h + i)·d_k + j. A .contiguous() copy would move 2·b·B·N·d bytes (read + write) per tensor. Read more: PyTorch docs: tensor views.

Why 1/√d_k

Derivation: for q, k with independent zero-mean, unit-variance entries, Var(q·k) = Σj Var(qjkj) = d_k, so the score's std is √d_k (8 at d_k = 64, 11.3 at 128). Softmax of numbers that large is nearly one-hot and its gradient vanishes. Dividing by √d_k brings the std back to 1 for any head size; it acts like a temperature.

Tiny example: d_k = 64, raw scores [8, 0]: softmax = [0.9997, 0.0003]. Scaled to [1, 0]: [0.73, 0.27], and both keys still get gradient.

Why the mask: in training, row i predicts token i + 1 from tokens 0…i, so it must not see later tokens. Online softmax: one pass, then no N × N at all

Safe softmax needs the row maximum before it can exponentiate. Online softmax (Milakov & Gimelshein 2018) keeps a running max m and sum l, and rescales l when a larger max arrives. FlashAttention adds a running, unnormalised output acc, rescaled the same way, so a tile's scores are used and discarded in on-chip SRAM.

m, l, acc = -inf, 0.0, 0.0              # running max, running sum, unnormalised output (one query row)
for S_blk, V_blk in tiles:              # S_blk = q · K_blk^T / sqrt(d_k) for one tile of keys
    m_new = max(m, S_blk.max())
    alpha = exp(m - m_new)              # shrink what was accumulated under the old max
    p = exp(S_blk - m_new)
    l, acc, m = l * alpha + p.sum(), acc * alpha + p @ V_blk, m_new
out = acc / l                           # == softmax(S) @ V, without storing S

    Q = self.W_q(x).view(B, N, self.n_heads, self.d_k).transpose(1, 2)   # blocks 3-4: [B, h, N, d_k]

    V = self.W_v(x).view(B, N, self.n_heads, self.d_k).transpose(1, 2)

    attn = self.dropout(torch.softmax(scores, dim=-1))               # block 7

2.6 TTFT: why prefill is compute-bound

TTFT ≈ prefill FLOPs ÷ achievable FLOP/s (when B·N rows ≫ ridge)

Why compute-bound: for a d × d weight, AI = 1 / (1/M + 2/d) = M / (1 + 2M/d) (§2.2): ≈ M while M ≪ d, approaching d/2 as M grows. It passes the ridge R when M > R / (1 − 2R/d), ≈ 231 rows at d = 4,096. In prefill M = B·N, so any prompt longer than a few hundred tokens is compute-bound (AI = 1,365 at N = 4,096).

3 Decode: one token per step against the cache

Each step feeds the newest token of every sequence, x [B, 1, d], through all L layers. Its q, k, v are computed, k and v are appended to the cache, and q attends over all t cached rows. Every weight is read once to produce B rows: decode is memory-bound.

3.2 No mask, no Q cache

  • No mask is needed. The new token sits at position t − 1, the last row of the causal mask, and row t − 1 of M is all zeros: Mt−1, j = 0 for every j ≤ t − 1. The cache holds only the past and the token itself, so there is nothing to block.
  • K and V are cached because they never change. With the causal mask, row j's K and V in every layer depend only on tokens 0…j, and every later query reads them.
  • Q is not cached. qj only produces row j's output, which was used once. See primer step 18, “What about Q?”.

3.3 FLOPs, bytes, intensity, TPOT

FLOPs/token ≈ 2·params + 4·L·t·d   ·   bytes/step ≈ b·params + B·2·L·n_kv·d_k·t·b

FLOPs: each matmul weight is used once per token, 2 FLOPs (multiply, add); attention adds q·K_cᵀ and softmax·V_c, 2·t·d_k per head each, so 4·t·d per layer. (Here “params” are the matmul weights, 12·L·d² + V·d; the position table is a lookup.)

Bytes: all weights once per step, shared by the B sequences, plus each sequence's own cache.

Intensity: a weight GEMM with M = B rows has AI = 2B / (b + 4B/d) ≈ B. Attention over the cache has AI = 4·t·h·d_k / (2·t·n_kv·d_k·b) = h / n_kv for FP16: 1 for MHA, whatever B is, because every sequence reads its own cache.

3.6 Cache growth and paged KV

  • Growth: every decode step appends 2·L·n_kv·d_k·b bytes per sequence: 512 KiB for the reference config. The cache, not the weights, often sets the maximum context and batch on a Jetson (§5).
  • Paged KV (vLLM's PagedAttention): store the cache in fixed-size blocks of a few tokens plus a block table per sequence, instead of one contiguous [t_max] buffer per sequence. Memory is allocated as tokens arrive, nothing is reserved for unused length, and sequences with a common prefix can share blocks. Cookbook card e.
  • Speculative decoding in one line: a small draft model proposes k tokens and the large model checks all k in one pass (M = k rows per weight read), keeping the large model's output distribution. Cookbook card g.

Prefill and decode

Every elementwise op in the §2.6 table is memory-bound: it reads and writes a whole [B, N, d] (or [B, N, d_ff]) tensor for one FLOP or a few. Fusing it into the GEMM before it (bias, GELU, residual add) or merging it with its neighbour (residual add + the next norm) removes that round trip. Per layer: GELU in W₁'s epilogue saves 2·b·B·N·d_ff bytes, the residual in W_O's epilogue 2·b·B·N·d, add + norm b·B·N·d per pair. The CUTLASS deep dive shows these epilogues in code. In decode the same ops are tiny, but each is still a kernel launch.

  • Epilogues. A GEMM kernel holds its output tile in registers before the store; bias, activation, residual add and even a quantize step can run there for free. Read more: CUTLASS deep dive (block 3); Triton tutorial: matrix multiplication.

  • Weight-only INT4 / INT8 (the usual LLM recipe on Jetson Orin): weights are stored in 4 or 8 bits and dequantized inside the GEMM; the maths stays FP16. Decode reads 2–4× fewer weight bytes: 13.2 → 37.4 tok/s for the reference model with INT4 (§3.3). Prefill is compute-bound and barely changes.
  • W8A8: INT8 weights and activations run on INT8 Tensor Cores, which have twice the FP16 rate, so they help prefill too.
  • Orin's precisions: FP16, INT8 and INT4; no FP8 or FP4 (those arrive with Ada/Hopper and Blackwell, e.g. Jetson Thor). See the cookbook's device table.
GPU kernel deep dive
  • Dequantize in registers. A weight-only GEMV loads packed 4-bit weights and their group scales, expands them to FP16 in registers and runs FP16 FMAs: the bytes shrink, the maths does not (block 3). Read more: cookbook card c.
  • Scales cost bytes too. One FP16 scale per group of g weights adds 16/g bits per weight; finer groups keep accuracy but read more. Read more: cookbook card c, granularity.
  • W8A8 on Tensor Cores. INT8 MMAs at twice the FP16 rate raise the compute roof for prefill, but the activations must be quantized on the fly, usually in the previous kernel's epilogue. Read more: NVIDIA, Matrix multiplication background.

7 Training in one screen

  • Same forward pass, full sequence. Training runs §2's prefill on [B, N] token sequences, but with the LM head on every row. The input at position i is the true token i, not a sampled one (teacher forcing).
  • N predictions per sequence, in parallel. The causal mask makes row i depend only on tokens 0…i, so one pass gives N independent next-token predictions. No KV cache is needed.
  • Loss: cross-entropy at every position, ℒ = −(1 / B·N) Σb,i log pθ(xb,i+1 | xb,≤i), with targets = ids shifted left by one.
  • Compute: backward costs about 2× forward (gradients for activations and for weights), so a step costs ≈ 3 × 2·params per token = 6·params·tokens. Reference config: 39.9 GFLOP per token, against 13.3 to generate one. GPT-2 small: 0.75 GFLOP per token; 10⁹ tokens is 7.46 × 10¹⁷ FLOP, 4.9 hours at AGX Orin's peak.
  • Memory: mixed-precision Adam keeps 16 bytes per parameter (weights, grads, FP32 master, two moments): 106.5 GB for the reference config, more than an AGX Orin has. Activations of every layer stay for backward: per layer ≈ B·N·d·(34 + 5·h·N/d) bytes (Korthikanti et al. 2022). The 5·h·N/d term is the stored scores, which FlashAttention recomputes instead; activation checkpointing keeps only each layer's input, 2·B·N·d bytes. Reference, all 32 layers: 104 GB, 18 GB without scores, 1 GB with checkpointing.

"""
Minimal Transformer Implementation (decoder-only, GPT-style)
Run: python transformer.py

This is a DECODER-ONLY (GPT-2-style) causal language model built from the
blocks of "Attention Is All You Need" (Vaswani et al., 2017). It is NOT the
paper's encoder-decoder model. Differences from the 2017 paper:
  - decoder only: no encoder and no cross-attention
  - pre-LayerNorm + a final LayerNorm   (paper: post-LN, x = LN(x + Sublayer(x)))
  - GELU in the FFN                     (paper: ReLU)
  - learned positional embeddings       (paper: sinusoidal; learned PE was an ablation)
  - no sqrt(d_model) scaling of the token embedding (GPT-2 convention; the paper
    multiplies by sqrt(d_model) and pairs it with sinusoidal PE)
  - no biases in the attention projections, GPT-2 init (normal, std 0.02)
Shared with the paper: scaled dot-product multi-head attention, the
position-wise FFN with d_ff = 4*d, residual connections, and tying the
embedding and output (LM-head) weights (paper Sec. 3.4).

This implementation prioritizes clarity over efficiency.
For production, use F.scaled_dot_product_attention / HuggingFace / TensorRT-LLM.

References:
- Paper: https://arxiv.org/abs/1706.03762 (Attention Is All You Need)
- PyTorch: https://pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html
"""

import torch
import torch.nn as nn
import torch.nn.functional as F


class MultiHeadAttention(nn.Module):
    """
    Multi-Head Attention mechanism.

    Args:
        d_model: Hidden dimension (embedding size)
        n_heads: Number of attention heads
        dropout: Dropout probability

    Shapes:
        Input:  [B, N, d_model]
        mask:   bool tensor broadcastable to [B, h, N, N].
                True = this query MAY attend to this key.
                Same convention as the bool attn_mask of F.scaled_dot_product_attention,
                but the OPPOSITE of nn.MultiheadAttention / nn.Transformer, where
                True (or -inf) means "blocked". A row with no True entry gives NaN.
        Output: [B, N, d_model]

    Reference: https://pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention.html
    """

    def __init__(self, d_model: int, n_heads: int, dropout: float = 0.1):
        super().__init__()
        assert d_model % n_heads == 0, "d_model must be divisible by n_heads"

        self.d_model = d_model
        self.n_heads = n_heads
        self.d_k = d_model // n_heads  # Dimension per head
        self.scale = self.d_k ** -0.5   # 1/sqrt(d_k)

        # Linear projections for Q, K, V
        # Reference: https://pytorch.org/docs/stable/generated/torch.nn.Linear.html
        self.W_q = nn.Linear(d_model, d_model, bias=False)
        self.W_k = nn.Linear(d_model, d_model, bias=False)
        self.W_v = nn.Linear(d_model, d_model, bias=False)
        self.W_o = nn.Linear(d_model, d_model, bias=False)

        self.dropout = nn.Dropout(dropout)
        self.last_attn = None  # attention weights of the last call (for inspection/demos)

    def forward(self, x: torch.Tensor, mask: torch.Tensor = None) -> torch.Tensor:
        B, N, _ = x.shape

        # Project to Q, K, V
        # Each: [B, N, d_model] @ [d_model, d_model] -> [B, N, d_model]
        # GPU: cuBLAS GEMM kernel
        Q = self.W_q(x)
        K = self.W_k(x)
        V = self.W_v(x)

        # Reshape for multi-head attention
        # [B, N, d_model] -> [B, N, n_heads, d_k] -> [B, n_heads, N, d_k]
        Q = Q.view(B, N, self.n_heads, self.d_k).transpose(1, 2)
        K = K.view(B, N, self.n_heads, self.d_k).transpose(1, 2)
        V = V.view(B, N, self.n_heads, self.d_k).transpose(1, 2)

        # Compute attention scores
        # [B, h, N, d_k] @ [B, h, d_k, N] -> [B, h, N, N]
        # This is O(N²) memory - the bottleneck!
        # GPU: cuBLAS batched GEMM (one small GEMM per (batch, head))
        scores = torch.matmul(Q, K.transpose(-2, -1)) * self.scale

        # Apply mask (for causal attention): blocked positions get -inf,
        # so exp(-inf) = 0 after the softmax.
        if mask is not None:
            assert mask.dtype == torch.bool, "mask must be bool, True = may attend"
            scores = scores.masked_fill(~mask, float('-inf'))

        # Softmax and dropout
        # Reference: https://pytorch.org/docs/stable/generated/torch.nn.functional.softmax.html
        attn_weights = F.softmax(scores, dim=-1)
        self.last_attn = attn_weights.detach()
        attn_weights = self.dropout(attn_weights)

        # Apply attention to values
        # [B, h, N, N] @ [B, h, N, d_k] -> [B, h, N, d_k]
        context = torch.matmul(attn_weights, V)

        # Reshape back
        # [B, h, N, d_k] -> [B, N, h, d_k] -> [B, N, d_model]
        context = context.transpose(1, 2).contiguous().view(B, N, self.d_model)

        # Output projection
        return self.W_o(context)


class FeedForward(nn.Module):
    """
    Position-wise Feed-Forward Network.

    FFN(x) = Linear2(GELU(Linear1(x)))      (the 2017 paper uses ReLU)

    Holds ~2/3 of each block's parameters (8d² of 12d², ignoring biases).

    Shapes:
        Input:  [B, N, d_model]
        Output: [B, N, d_model]

    Reference: https://pytorch.org/docs/stable/generated/torch.nn.GELU.html
    """

    def __init__(self, d_model: int, d_ff: int = None, dropout: float = 0.1):
        super().__init__()
        d_ff = d_ff or 4 * d_model  # Default: 4x expansion

        self.linear1 = nn.Linear(d_model, d_ff)
        self.linear2 = nn.Linear(d_ff, d_model)
        self.dropout = nn.Dropout(dropout)
        self.activation = nn.GELU()

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # [B, N, d] -> [B, N, d_ff] -> [B, N, d]
        x = self.linear1(x)      # GPU: cuBLAS GEMM
        x = self.activation(x)   # GPU: Elementwise kernel
        x = self.dropout(x)
        x = self.linear2(x)      # GPU: cuBLAS GEMM
        return x


class TransformerBlock(nn.Module):
    """
    Single Transformer block with pre-normalization (GPT-2 style).

    Structure:
        x = x + Attention(LayerNorm(x))
        x = x + FFN(LayerNorm(x))
    (The 2017 paper uses post-norm: x = LN(x + Sublayer(x)).)

    Reference: https://pytorch.org/docs/stable/generated/torch.nn.LayerNorm.html
    """

    def __init__(self, d_model: int, n_heads: int, d_ff: int = None, dropout: float = 0.1):
        super().__init__()

        self.norm1 = nn.LayerNorm(d_model)
        self.attn = MultiHeadAttention(d_model, n_heads, dropout)

        self.norm2 = nn.LayerNorm(d_model)
        self.ffn = FeedForward(d_model, d_ff, dropout)

        self.dropout = nn.Dropout(dropout)

    def forward(self, x: torch.Tensor, mask: torch.Tensor = None) -> torch.Tensor:
        # Pre-norm + residual for attention
        x = x + self.dropout(self.attn(self.norm1(x), mask))

        # Pre-norm + residual for FFN
        x = x + self.dropout(self.ffn(self.norm2(x)))

        return x


class Transformer(nn.Module):
    """
    Complete decoder-only Transformer language model.

    Args:
        vocab_size:   Size of vocabulary (V)
        d_model:      Hidden dimension (d)
        n_heads:      Number of attention heads (h)
        n_layers:     Number of transformer blocks (L)
        d_ff:         Feed-forward hidden dimension (d_ff, default 4*d)
        max_seq_len:  Maximum sequence length (N_max)
        dropout:      Dropout probability

    Shapes:
        Input:  [B, N] token ids
        Output: [B, N, V] logits (row i = scores for the token at position i+1)

    Reference: https://pytorch.org/docs/stable/generated/torch.nn.Embedding.html
    """

    def __init__(
        self,
        vocab_size: int,
        d_model: int = 512,
        n_heads: int = 8,
        n_layers: int = 6,
        d_ff: int = None,
        max_seq_len: int = 512,
        dropout: float = 0.1
    ):
        super().__init__()

        self.d_model = d_model
        self.n_layers = n_layers

        # Token and position embeddings
        self.token_emb = nn.Embedding(vocab_size, d_model)
        self.pos_emb = nn.Embedding(max_seq_len, d_model)
        self.dropout = nn.Dropout(dropout)

        # Transformer blocks
        self.layers = nn.ModuleList([
            TransformerBlock(d_model, n_heads, d_ff, dropout)
            for _ in range(n_layers)
        ])

        # Final layer norm
        self.norm = nn.LayerNorm(d_model)

        # Output projection to vocabulary (the "LM head")
        self.output = nn.Linear(d_model, vocab_size, bias=False)

        # Tie weights with token embeddings (common practice)
        self.output.weight = self.token_emb.weight

        # Initialize weights
        self.apply(self._init_weights)

    def _init_weights(self, module):
        if isinstance(module, nn.Linear):
            torch.nn.init.normal_(module.weight, mean=0.0, std=0.02)
            if module.bias is not None:
                torch.nn.init.zeros_(module.bias)
        elif isinstance(module, nn.Embedding):
            torch.nn.init.normal_(module.weight, mean=0.0, std=0.02)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B, N = x.shape
        assert N <= self.pos_emb.num_embeddings, (
            f"sequence length {N} > max_seq_len {self.pos_emb.num_embeddings} "
            "(learned positional embeddings cannot extrapolate)")

        # Causal mask: True = may attend. Query i sees keys 0..i (lower triangle).
        mask = torch.tril(torch.ones(N, N, dtype=torch.bool, device=x.device))

        # Embeddings: row lookup in the [V, d] table + a learned position vector.
        # GPT-2 style: no sqrt(d_model) scaling (see module docstring).
        positions = torch.arange(N, device=x.device).unsqueeze(0)
        x = self.token_emb(x)
        x = x + self.pos_emb(positions)
        x = self.dropout(x)

        # Transformer layers
        for layer in self.layers:
            x = layer(x, mask)

        # Output
        x = self.norm(x)
        logits = self.output(x)

        return logits

    def count_parameters(self) -> int:
        """Count total trainable parameters (tied weights counted once)."""
        return sum(p.numel() for p in self.parameters() if p.requires_grad)

def compute_flops(B: int, N: int, d: int, h: int, d_ff: int, L: int, V: int = 0) -> dict:
    """
    FLOPs of one forward pass over N tokens (2 FLOPs per multiply-accumulate).

    Counts the matmuls of the L blocks and the LM head (2*B*N*d*V; pass V=0 to
    skip it), plus a 5*h*N² softmax estimate. Ignores LayerNorm, GELU, residual
    adds, the embedding gather, and the ~2x saving a causal kernel can get by
    skipping masked scores.

    All keys except 'per_layer' are summed over the L layers;
    'per_layer' is ONE layer (softmax included, LM head excluded).
    """
    # Per layer
    qkv = 6 * B * N * d * d
    qkt = 2 * B * N * N * d
    softmax = 5 * B * h * N * N
    av = 2 * B * N * N * d
    out_proj = 2 * B * N * d * d
    ffn = 4 * B * N * d * d_ff

    per_layer = qkv + qkt + softmax + av + out_proj + ffn
    lm_head = 2 * B * N * d * V
    total = L * per_layer + lm_head

    return {
        'qkv_projection': qkv * L,
        'qk_transpose': qkt * L,
        'softmax': softmax * L,
        'attn_v': av * L,
        'out_projection': out_proj * L,
        'ffn': ffn * L,
        'lm_head': lm_head,
        'per_layer': per_layer,
        'total': total
    }


def compute_memory(B: int, N: int, d: int, h: int, dtype_bytes: int = 4) -> dict:
    """
    Memory of ONE layer, in bytes.
    attention_scores: the naive [B, h, N, N] score matrix. At inference it is
                      freed before the next layer runs; FlashAttention never stores it.
    kv_cache:         K and V for N tokens with classic multi-head attention
                      (with grouped-query attention, multiply by n_kv_heads / h).
    """
    return {
        'attention_scores': B * h * N * N * dtype_bytes,
        'kv_cache': 2 * B * N * d * dtype_bytes,
        'activations': B * N * d * dtype_bytes,
    }


def format_number(n: float) -> str:
    """Format large numbers with K/M/G/T/P suffixes (powers of 1000)."""
    for div, suffix in ((1e15, "P"), (1e12, "T"), (1e9, "G"), (1e6, "M"), (1e3, "K")):
        if abs(n) >= div:
            return f"{n/div:.2f}{suffix}"
    return f"{n:.0f}"


def format_bytes(b: float) -> str:
    """Format bytes with binary units (KiB/MiB/GiB/TiB, powers of 1024)."""
    for div, suffix in ((2**40, "TiB"), (2**30, "GiB"), (2**20, "MiB"), (2**10, "KiB")):
        if b >= div:
            return f"{b/div:.2f} {suffix}"
    return f"{b:.0f} B"

def demo_causality():
    """Show the causal attention pattern and why it makes a KV cache valid."""
    print("\n" + "=" * 70)
    print("DEMO: Causal mask => past tokens never change => KV cache is valid")
    print("=" * 70)

    torch.manual_seed(0)
    model = Transformer(vocab_size=1000, d_model=64, n_heads=4, n_layers=2, max_seq_len=64)
    model.eval()
    x = torch.randint(0, 1000, (1, 8))

    with torch.no_grad():
        logits = model(x)
        w = model.layers[0].attn.last_attn[0, 0, :5, :5]  # layer 0, head 0, first 5 tokens
    print("\nAttention weights, layer 0 / head 0 (rows = query i, cols = key j):")
    for i, row in enumerate(w.tolist()):
        print(f"  q{i}: " + " ".join(f"{v:5.2f}" for v in row))
    print("  -> upper triangle is exactly 0 (no peeking ahead); each row sums to 1.")
    print("     An untrained model spreads weight almost evenly: ~1, 1/2, 1/3, 1/4, 1/5.")

    with torch.no_grad():
        prefix_logits = model(x[:, :5])
    same = torch.allclose(logits[:, :5], prefix_logits, atol=1e-5)
    print(f"\nLogits of tokens 0..4 unchanged when tokens 5..7 are appended? {same}")
    print("  -> K, V of old tokens never change, so they can be computed once and cached.")

Key takeaways

  • The model is 11 equations (§1): embed, then L × [x += attn(LN(x)); x += FFN(LN(x))], then LN_f and the LM head. About 12·L·d² + V·d parameters.
  • The head split reshapes Q's output columns; every head's projection reads all d inputs. One [d × d] GEMM equals the paper's h separate [d × d_k] projections.
  • Prefill: GEMMs with M = B·N rows, FLOPs L·(24Nd² + 4N²d), compute-bound, TTFT ≈ FLOPs ÷ FLOP/s. The N² scores are a prefill problem; FlashAttention removes their memory and traffic, not their FLOPs.
  • Prefill writes K and V, [B, n_kv, N, d_k] per layer. The causal mask keeps them valid; decode needs no mask and no Q cache.
  • Decode: GEMVs with M = B, ≈ 2·params + 4·L·t·d FLOPs over b·params + KV bytes, AI ≈ 1, memory-bound, TPOT ≈ bytes ÷ bandwidth: ≈ 13 tok/s for the 7B-class FP16 model on AGX Orin at t = 4,096.
  • Decode gets faster by moving fewer bytes (INT4 weights, GQA, KV quantization) or using each byte more (batching, speculative decoding); prefill by doing fewer or faster FLOPs and fusing.
  • Memory: weights, KV cache (2·L·n_kv·d_k·b per token) and one layer's activations at inference; every layer's activations plus 16 B/param of optimizer state in training.

Self-check

Try each question before opening the answer.

1. d = 4096 and h = 32. What is d_k, and what is the shape of the scores for B = 2, N = 128?

Answer

d_k = 4096 / 32 = 128. Scores are [B, h, N, N] = [2, 32, 128, 128].

2. In the reference model, how many of a token's 4,096 input numbers does head 3's query read, and how big is the paper's W3Q?

Answer

All 4,096: every column of Q is a dot product with the whole token. W3Q is [4096 × 128], columns 384–511 of W_Q. The 32 heads' matrices side by side are the [4096 × 4096] W_Q, so the parameter count is the same either way.

3. You double the prompt length N. By how much do the QKV FLOPs and the Q·Kᵀ FLOPs grow, and what happens to the unfused score memory?

Answer

QKV is 6·B·N·d², linear: 2×. Q·Kᵀ is 2·B·N²·d, quadratic: 4×. The unfused score tensor B·h·N²·b also grows 4×.

4. Why does a decode step need no causal mask, and why is Q not cached?

Answer

The new token is the last row; every key in the cache is at a position ≤ its own, so its mask row is all zeros. Q is used once, to produce its own row's output; old queries are never read again, while every later query reads all K and V.

5. Llama 2 7B has L = 32, d = 4096 and 32 K/V heads of 128. In FP16, how big is its KV cache per token and at 4,096 tokens? And with 8 K/V heads?

Answer

2 × 32 × 32 × 128 × 2 B = 512 KiB per token, 2 GiB at 4,096 tokens per sequence. With 8 K/V heads: 128 KiB per token, 512 MiB: 4× smaller.

6. The reference model decodes at B = 1, t = 4,096 on an AGX Orin. Is it compute- or memory-bound, what is the bound on tokens/s, and what do INT4 weights give?

Answer

Memory-bound: 15.44 GFLOP over 15.46 GB is AI ≈ 1, far below the ridge of 208. TPOT ≥ 15.46 GB ÷ 204.8 GB/s = 75.5 ms, ≈ 13 tok/s. INT4 weights: 3.33 + 2.15 = 5.48 GB per step, ≈ 37 tok/s; the cache read now matters as much as the weights.

7. Batching B sequences multiplies decode throughput for the weight GEMMs. Why does it not raise the intensity of attention over the cache?

Answer

Each sequence reads its own cache, so cache bytes grow with B just like attention FLOPs. Per sequence, AI = 4·t·h·d_k ÷ (2·t·n_kv·d_k·2 B) = h / n_kv: 1 for MHA, 4 for GQA-8, whatever B is.

8. Bound the TTFT of a 4,096-token prompt for the reference model on an AGX Orin. Is a 128-token prompt bound the same way?

Answer

61.57 TFLOP ÷ 42.5 TFLOPS ≥ 1.45 s, compute-bound (GEMM AI 1,365). A 128-token prompt needs 1.66 TFLOP (39 ms of compute) but still reads all 13.31 GB of weights (65 ms): it is memory-bound, like decode.

9. What does FlashAttention change: the FLOPs, the extra memory, the DRAM traffic, the result? Does it help decode?

Answer

FLOPs: the same. Extra memory: O(N²) → O(N), only the row statistics. DRAM traffic: no N × N round trips. Result: identical up to rounding. Decode has one query row and no N × N matrix, so its gain there is small; decode is bound by the weight and cache reads.

10. Roughly what does training the reference model cost per token, and why can you not fully fine-tune it on an AGX Orin 64GB?

Answer

6·params ≈ 39.9 GFLOP per token. Mixed-precision Adam needs 16 B per parameter, 106.5 GB, before activations: more than 64 GB. LoRA/QLoRA with checkpointing is the edge recipe (cookbook card j).
