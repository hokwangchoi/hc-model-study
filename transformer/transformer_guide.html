2. Why Attention Works: The Core Intuition

Before diving into dimensions and code, let's understand why attention is such a powerful mechanism. (Based on 3Blue1Brown's excellent explanation)

2a. Attention with real numbers (one head, 3 tokens)

Attention is a soft dictionary lookup. A Python dict returns the one value whose key equals the query. Attention instead returns a blend of all values, weighted by how well each key matches the query. In hardware terms: a content-addressable memory that returns a weighted average instead of a single hit. Here is one lookup by hand, with d_k = 4.

What to notice: (1) rotate the query toward a key and that key's weight rises: the dot product measures alignment. (2) r = 0 gives a plain average; a long query gives a near-hard lookup, so the query's length acts like an inverse temperature. (3) The output (filled circle) always stays inside the triangle of value points: attention can only blend values. W_o and the FFN are what create new features.

Why divide by √d_k?

Each term qᵢkᵢ of a dot product between random unit-variance vectors has variance 1, so a sum of d_k terms has variance d_k and standard deviation √d_k. Without scaling, a d_k = 128 head produces scores with std ≈ 11, and softmax of such large numbers is almost one-hot: one key takes nearly all the weight and the gradients of the others vanish. Dividing by √d_k brings the std back to about 1 for any head size. It is the same job as scaling a signal into an ADC's range before a saturating stage, and the same knob as the sampling temperature T in softmax(logits / T).

Eight keys whose scaled scores are fixed at [1.2, −0.3, 0.5, −1.1, 0.8, 0.1, −0.6, 0.3]. Without the 1/√d_k factor the raw scores are √d_k times larger. What to notice: unscaled, the largest weight climbs from 0.49 (d_k = 4) to 0.96 (d_k = 64) to ≈1.00 (d_k = 512); scaled, it stays 0.29 for every d_k.

3. The causal mask: no peeking ahead

A decoder is trained to predict token i+1 from tokens 0…i. If position i could see token i+1, the task would be copying. The causal mask sets every score with key j > query i to −∞ before the softmax, so each row only spreads its weight over the past. Click through the three stages, toggle the mask, and click a row to focus on one query.

  • Why −∞? softmax uses exp, and exp(−∞) = 0, so masked keys get exactly zero weight while the visible weights still sum to 1. (Row 0 can only see itself, so its weight is always 1.)
  • Why it makes training parallel: one forward pass over a sentence of N tokens yields N next-token predictions at once, each using only its own past. That is the "parallel" advantage over RNNs from the comparison at the top of this section.
  • Why it matters for inference: token i never looks at later tokens, so appending a token cannot change the keys, values or outputs of earlier tokens. They can be computed once and cached: that is the KV-cache in the next section. (demo_causality() in transformer.py checks exactly this.) A bidirectional encoder such as ViT has no such guarantee.
  • Reading the code: mask = torch.tril(torch.ones(N, N, dtype=torch.bool)) is True where the query may attend (j ≤ i); scores.masked_fill(~mask, -inf) blocks the rest. PyTorch's fused path does the same with F.scaled_dot_product_attention(q, k, v, is_causal=True). Watch the polarity: in nn.MultiheadAttention a True (or −∞) mask entry means blocked.

Why cache K and V, but not Q?

  • A query is used once. qi only produces token i's own output. Old outputs are already done, so old queries are never needed again.
  • Keys and values are read by every future query, and the causal mask guarantees they never change. Caching them is plain memoization.
  • Each decode step still computes q, k and v for the new token, appends its k and v to the cache, and attends over the whole cache.
  • The bigger saving is not attention. Without a cache, step t pushes all t tokens through every weight matrix (QKV, W_o, FFN); with it, only one token does. For this 15-step example the token-rows through those GEMMs drop from 200 to 20, and the causal score pairs (per head, per layer) from 1,520 to 210, counting the 5-token prefill.
  • Why decode is still slow: one token per step means every weight byte read from memory is used for a single row of work. Decode is memory-bandwidth-bound; see arithmetic intensity in §4. Mamba (Module 5) replaces this ever-growing cache with a fixed-size state.
Edge deployment insight (Jetson/DRIVE)

On memory-constrained devices the KV-cache often sets the maximum context length. Per sequence it holds 2 × L × N × n_kv_heads × d_k × bytes (n_kv_heads = h for classic multi-head attention). The main levers: grouped-/multi-query attention (fewer K/V heads; Llama 3 8B keeps 8 K/V heads for 32 query heads, a 4× smaller cache), FP8/INT8 KV-cache quantization, PagedAttention (vLLM) against fragmentation, and sliding-window attention.

Input Embeddings + Positional Encoding
Input: [B, N] → Output: [B, N, d]
Memory-bound

What it does

Converts discrete token IDs into vectors: an embedding is just a row lookup in a learned [V, d] table. Positions must be added because attention by itself has no notion of order: without a mask, shuffling the input tokens just shuffles the outputs the same way.

Mathematical formula
X = Embedding(tokens) + PositionalEncoding(positions)
Embedding: Lookup table of shape [V, d]
Positional encoding: sinusoidal (2017 paper) or learned (GPT-2, BERT, this guide) table of shape [N_max, d], added to the embeddings. Modern LLMs (Llama, Mistral, Qwen) instead use RoPE, a rotation applied to Q and K inside every attention layer (see "What changed since 2017" below).

import torch
import torch.nn as nn

class TransformerEmbedding(nn.Module):
    def __init__(self, vocab_size, d_model, max_seq_len, dropout=0.1):
        super().__init__()
        self.token_emb = nn.Embedding(vocab_size, d_model)  # [V, d]
        self.pos_emb = nn.Embedding(max_seq_len, d_model)   # [N_max, d]
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        # x: [B, N] token indices
        B, N = x.shape
        positions = torch.arange(N, device=x.device).unsqueeze(0)  # [1, N]

        # GPT-2 style: no sqrt(d_model) scaling. (The 2017 paper multiplies by
        # sqrt(d_model) and pairs it with sinusoidal PE; with small learned
        # embeddings that factor would drown out the position signal.)
        tok = self.token_emb(x)          # [B, N, d]  row lookup (gather)
        pos = self.pos_emb(positions)    # [1, N, d]  broadcast over B

        return self.dropout(tok + pos)  # [B, N, d]

GPU kernel considerations

Embedding lookup is a gather operation: it reads B·N rows of d values and does no arithmetic, so it is memory-bound. It is tiny next to the GEMMs, but the [V, d] table itself is large (Llama 3's V = 128,256). Options:

  • Fused embedding + position addition
  • Quantized embeddings (INT8)
  • Tensor parallelism across vocabulary dimension

Layer Normalization
Input: [B, N, d] → Output: [B, N, d]
Memory-bound

What it does

Rescales each token's d-vector to zero mean and unit variance, then applies a learned per-channel gain γ and offset β. Think of it as automatic gain control in front of each sub-layer: the sub-layer sees inputs in a predictable range however large the residual stream has grown. This keeps deep stacks stable and fast to train. (The original "internal covariate shift" explanation is now considered incomplete.)

Tiny example: x = [2, 4, 6, 8] → μ = 5, σ² = 5 → (x − μ)/σ ≈ [−1.34, −0.45, 0.45, 1.34]. Llama-style models use RMSNorm instead: skip the mean and divide by √mean(x²) = √30 ≈ 5.48, giving ≈ [0.37, 0.73, 1.10, 1.46].

Mathematical formula
LayerNorm(x) = γ × (x - μ) / √(σ² + ε) + β
μ: mean(x) over d dimension
σ²: variance(x) over d dimension (biased: divide by d, not d−1)
γ, β: learned scale and shift parameters [d]
ε: small constant for numerical stability (1e-5)

PyTorch implementation

class LayerNorm(nn.Module):
    """Manual implementation to understand the operations"""
    def __init__(self, d_model, eps=1e-5):
        super().__init__()
        self.gamma = nn.Parameter(torch.ones(d_model))   # [d]
        self.beta = nn.Parameter(torch.zeros(d_model))   # [d]
        self.eps = eps

    def forward(self, x):
        # x: [B, N, d]
        # Compute mean and variance over last dimension
        mean = x.mean(dim=-1, keepdim=True)    # [B, N, 1]
        var = x.var(dim=-1, keepdim=True, unbiased=False)  # [B, N, 1], ÷d like nn.LayerNorm

        # Normalize
        x_norm = (x - mean) / torch.sqrt(var + self.eps)  # [B, N, d]

        # Scale and shift
        return self.gamma * x_norm + self.beta  # [B, N, d]

# Or just use PyTorch's optimized version:
layer_norm = nn.LayerNorm(d_model)  # Uses fused CUDA kernel

# Check: matches nn.LayerNorm (the default unbiased var would not)
x = torch.randn(2, 3, 64)
assert torch.allclose(LayerNorm(64)(x), nn.LayerNorm(64)(x), atol=1e-5)

GPU kernel considerations

LayerNorm is memory-bound because it requires:

  1. Pass 1: Read all d elements to compute mean
  2. Pass 2: Read all d elements again to compute variance
  3. Pass 3: Read all d elements, normalize, write back

It does only a few FLOPs per byte. Optimization: fused kernels (PyTorch, Apex, TensorRT) keep one token's row on chip, compute mean and variance in one sweep (e.g. Welford's algorithm), and normalize before writing back: one read and one write instead of three passes.

Multi-Head Attention
Input: [B, N, d] → Output: [B, N, d]
Compute + Memory

What it does

Lets each position gather information from other positions (in a decoder: only earlier ones, via the causal mask). Multiple "heads" learn different attention patterns in parallel, each on its own d_k-sized slice of the projected vectors.

Scaled dot-product attention
Attention(Q, K, V) = softmax(QKᵀ / √d_k) × V
Q, K, V: Query, Key, Value matrices — linear projections of input
√d_k: keeps the score standard deviation ≈ 1 so the softmax does not saturate (see 2b)
Multi-head formulation
MultiHead(X) = Concat(head₁, ..., headₕ) × Wᵒ
headᵢ: Attention(X×Wᵢᵠ, X×Wᵢᴷ, X×Wᵢⱽ)
Wᵒ: Output projection [h×d_v, d]

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_heads, dropout=0.1):
        super().__init__()
        assert d_model % n_heads == 0

        self.d_model = d_model
        self.n_heads = n_heads
        self.d_k = d_model // n_heads

        # Q, K, V projections (often fused into single weight)
        self.W_q = nn.Linear(d_model, d_model, bias=False)
        self.W_k = nn.Linear(d_model, d_model, bias=False)
        self.W_v = nn.Linear(d_model, d_model, bias=False)
        self.W_o = nn.Linear(d_model, d_model, bias=False)

        self.dropout = nn.Dropout(dropout)
        self.scale = self.d_k ** -0.5

    def forward(self, x, mask=None):
        B, N, _ = x.shape

        # Project to Q, K, V: [B, N, d] → [B, N, d]
        Q = self.W_q(x)  # GEMM: [B, N, d] × [d, d]
        K = self.W_k(x)  # GEMM: [B, N, d] × [d, d]
        V = self.W_v(x)  # GEMM: [B, N, d] × [d, d]

        # Reshape for multi-head: [B, N, d] → [B, h, N, d_k]
        Q = Q.view(B, N, self.n_heads, self.d_k).transpose(1, 2)
        K = K.view(B, N, self.n_heads, self.d_k).transpose(1, 2)
        V = V.view(B, N, self.n_heads, self.d_k).transpose(1, 2)

        # Attention scores: [B, h, N, d_k] × [B, h, d_k, N] → [B, h, N, N]
        scores = torch.matmul(Q, K.transpose(-2, -1)) * self.scale

        # Apply causal mask if provided (bool, True = may attend)
        if mask is not None:
            scores = scores.masked_fill(~mask, float('-inf'))

        # Softmax over last dimension (memory-bound!)
        attn_weights = torch.softmax(scores, dim=-1)
        attn_weights = self.dropout(attn_weights)

        # Apply attention to values: [B, h, N, N] × [B, h, N, d_k] → [B, h, N, d_k]
        context = torch.matmul(attn_weights, V)

        # Reshape back: [B, h, N, d_k] → [B, N, d]
        context = context.transpose(1, 2).contiguous().view(B, N, self.d_model)

        # Output projection
        return self.W_o(context)  # GEMM: [B, N, d] × [d, d]

Quadratic memory bottleneck

The QKᵀ matmul produces an [N, N] matrix per head. For N=4096, h=32 in FP16 that's 32 × 4096 × 4096 × 2 bytes = 1 GiB per layer (2 GiB in FP32), per sequence. This is why FlashAttention was invented.

Softmax
Input: [B, h, N, N] → Output: [B, h, N, N]
Memory-bound

What it does

Converts raw attention scores into a probability distribution over keys. Applied row-wise (each query has a distribution over all keys).

Standard softmax (numerically unstable)
softmax(xᵢ) = exp(xᵢ) / Σⱼ exp(xⱼ)
Safe softmax (subtract max for stability)
softmax(xᵢ) = exp(xᵢ - max(x)) / Σⱼ exp(xⱼ - max(x))
Subtracting max prevents overflow in exp() while giving identical results.

PyTorch implementation

Python PyTorch docs → 
def safe_softmax(x, dim=-1):
    """Manual implementation showing the 3 passes"""
    # Pass 1: Find max (read all elements)
    x_max = x.max(dim=dim, keepdim=True).values

    # Pass 2: Compute exp and sum (read all elements)
    x_exp = torch.exp(x - x_max)
    x_sum = x_exp.sum(dim=dim, keepdim=True)

    # Pass 3: Normalize (read exp, write output)
    return x_exp / x_sum

# PyTorch's version is fused and faster:
output = torch.softmax(scores, dim=-1)

Online softmax (Milakov & Gimelshein 2018, the trick inside FlashAttention)

Safe softmax needs the row maximum before it can exponentiate anything, so it reads the scores three times. Online softmax keeps a running max m and running sum l, and rescales l whenever a larger max appears. That merges the max and sum passes. FlashAttention goes one step further: it also keeps a running, unnormalised output acc and rescales it the same way, so the N×N scores never have to be stored or re-read.

Algorithm (one query row) FlashAttention paper → 
m, l, acc = -inf, 0.0, 0.0      # running max, running sum, running (unnormalised) output
for S_blk, V_blk in tiles:        # S_blk = q · K_blkᵀ / √d_k for one tile of keys
    m_new = max(m, S_blk.max())
    alpha = exp(m - m_new)        # shrink everything accumulated so far
    p     = exp(S_blk - m_new)
    l     = l * alpha + p.sum()
    acc   = acc * alpha + p @ V_blk
    m     = m_new
out = acc / l                     # == softmax(S) @ V, without ever storing S

Residual Connection (Add)
Inputs: [B, N, d] + [B, N, d] → Output: [B, N, d]
Memory-bound

What it does

Think of x as a shared data bus, the residual stream. Each sub-layer reads the bus, computes a small correction and adds it back: x ← x + f(LN(x)). Nothing is overwritten, so information from the embedding can reach the last layer unchanged, and gradients get a direct path back through the stack (critical for training deep networks). Because every block reads and writes the same [B, N, d] bus, the shape never changes inside the stack.

Mathematical formula
output = x + SubLayer(LayerNorm(x))
Pre-norm (modern): normalize before sub-layer
Post-norm (original): normalize after add

PyTorch implementation

Python 
class PreNormResidual(nn.Module):
    """Pre-norm style (GPT-2, LLaMA, modern transformers)"""
    def __init__(self, d_model, sublayer):
        super().__init__()
        self.norm = nn.LayerNorm(d_model)
        self.sublayer = sublayer

    def forward(self, x):
        # Residual: x + f(norm(x))
        return x + self.sublayer(self.norm(x))

class PostNormResidual(nn.Module):
    """Post-norm style (original Transformer, BERT)"""
    def __init__(self, d_model, sublayer):
        super().__init__()
        self.norm = nn.LayerNorm(d_model)
        self.sublayer = sublayer

    def forward(self, x):
        # Residual: norm(x + f(x))
        return self.norm(x + self.sublayer(x))

GPU optimization

Residual add is just an elementwise operation, but it is usually fused with the next LayerNorm to avoid an extra memory round-trip (compilers such as torch.compile and TensorRT do this for you):

// Fused kernel does:

Feed-Forward Network (FFN)
Input: [B, N, d] → Output: [B, N, d]
Compute (prefill) · Memory (decode)

What it does

Attention only moves information between tokens; apart from the softmax it is a weighted average. The FFN is where each token, on its own, transforms what it gathered: expand to 4d, apply a nonlinearity, project back. A useful picture (Geva et al., 2021): the d_ff hidden units are pattern detectors (rows of W₁ act like keys); when one fires, it writes a learned vector into the residual stream (columns of W₂ act like values). The FFN is a big key–value memory, which is why about 2/3 of each block's parameters live here, and roughly 2/3 of the FLOPs for short sequences.

Mathematical formula
FFN(x) = Linear₂(Activation(Linear₁(x)))
Linear₁: [d, d_ff] — expands to 4× width
Activation: GELU or SiLU (modern) or ReLU (original)
Linear₂: [d_ff, d] — projects back down

class FeedForward(nn.Module):
    def __init__(self, d_model, d_ff=None, dropout=0.1):
        super().__init__()
        d_ff = d_ff or 4 * d_model  # Standard: 4× expansion

        self.linear1 = nn.Linear(d_model, d_ff)   # [d, d_ff]
        self.linear2 = nn.Linear(d_ff, d_model)   # [d_ff, d]
        self.activation = nn.GELU()               # Smooth ReLU variant
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        # x: [B, N, d]
        x = self.linear1(x)      # GEMM: [B, N, d] × [d, d_ff] → [B, N, d_ff]
        x = self.activation(x)   # Elementwise GELU
        x = self.dropout(x)
        x = self.linear2(x)      # GEMM: [B, N, d_ff] × [d_ff, d] → [B, N, d]
        return x

# Modern variant: SwiGLU (used in Llama, PaLM): a gate decides what passes
class SwiGLU(nn.Module):
    def __init__(self, d_model, d_ff=None):
        super().__init__()
        d_ff = d_ff or int(2/3 * 4 * d_model)  # Adjusted for gating

        self.w1 = nn.Linear(d_model, d_ff, bias=False)
        self.w2 = nn.Linear(d_ff, d_model, bias=False)
        self.w3 = nn.Linear(d_model, d_ff, bias=False)  # Gate

    def forward(self, x):
        return self.w2(nn.functional.silu(self.w1(x)) * self.w3(x))

Parameter count

For standard FFN with d_ff = 4d:

  • Linear₁: d × d_ff = d × 4d = 4d² parameters
  • Linear₂: d_ff × d = 4d × d = 4d² parameters
  • Total: 8d² parameters per layer

Compare to attention: ~4d² (QKV + output), so FFN has 2× the parameters. (Plus small biases d_ff + d, which print_model_summary() in transformer.py includes.)

Final LayerNorm + LM head
Input: [B, N, d] → Output: logits [B, N, V]
Compute (prefill) · Memory (decode)

What it does

After the last block, one more LayerNorm and a [d, V] linear layer turn each token's vector into V logits, one score per vocabulary entry. Row i of the logits scores the token at position i+1. With weight tying the LM head reuses the [V, d] embedding table, which saves V·d parameters (38.6M for GPT-2 Small: V = 50,257, d = 768).

Inference notes

  • The LM head costs 2·N·d·V FLOPs. With a large vocabulary that is not small: for GPT-2 Small over 1,024 tokens it is about 27% of the forward pass.
  • Generation only needs the last row, so inference engines usually apply the LM head to the last position only. Full [N, V] logits for N = 2048, V = 50,257 in FP16 would be about 196 MiB.

Key insight

Per layer, FLOPs ≈ 24·N·d² + 4·N²·d (with d_ff = 4d), so the FFN's share is 16d / (24d + 4N). It is the largest term for short sequences (about 2/3 when N ≪ d, 61.5% at N = 2048, d = 4096), but attention's share grows linearly with N: at N = 2d the FFN is down to 50%. And attention's naive O(N²) score memory is the bigger problem for long sequences. That is why FlashAttention targets attention, not the FFN.

Arithmetic intensity: why decode is slow on Jetson Orin

FLOPs alone do not tell you how long a kernel takes. Every kernel also moves bytes between DRAM and the chip. Arithmetic intensity AI = FLOPs ÷ bytes moved. A device that does P FLOP/s and moves BW bytes/s has a ridge point P / BW:

  • AI below the ridge: the ALUs wait for memory, so the kernel is memory-bound and runs at AI × BW.
  • AI above the ridge: memory waits for the ALUs, so it is compute-bound and runs at up to P.

For a linear layer y = x·W with x : [M, d] and W : [d, d] in FP16, FLOPs = 2·M·d² and bytes ≈ 2·d² (weights) + 4·M·d (activations in and out). When M ≪ d, AI ≈ M: each weight byte is used once per row of x. In decode M = batch size (1 on a typical edge device), so AI ≈ 1. In prefill M = batch × prompt length, e.g. 512, so AI ≈ 410.

Jetson AGX Orin 64GB: its GPU does about 42.5 TFLOPS of dense FP16 on Tensor Cores (half of the 85 dense INT8 TOPS implied by the datasheet's 170 sparse INT8 TOPS) and reads LPDDR5 at 204.8 GB/s, so the ridge is about 208 FLOP/byte. Decode at AI ≈ 1 uses well under 1% of the Tensor Cores. Each generated token must stream every weight once: a 7B-parameter model in FP16 is about 14 GB, which caps decode at 204.8 / 14 ≈ 15 tokens/s however many TFLOPS the GPU has. 4-bit weights (≈3.5 GB) raise that ceiling about 4×. Batching B requests sets M = B and reuses every weight byte B times.

6 GPU Optimization Techniques

Key optimization strategies for NVIDIA platforms (TensorRT, CUDA, Tensor Cores).

Kernel fusion

🔥
FlashAttention — Fused attention kernel
2-4× speedup, O(N) extra memory instead of O(N²), same FLOPs

The problem: O(N²) memory bottleneck

Standard attention materializes the full N×N score matrix in GPU DRAM: HBM (High Bandwidth Memory) on data-center GPUs, LPDDR5 shared with the CPU on Jetson. For N=4096, h=32 that's 1 GiB per layer in FP16 (2 GiB in FP32) per sequence, just for intermediate values, and it is written and read back several times.

The solution: Tiled computation in SRAM

FlashAttention processes Q, K, V in small tiles that fit in fast on-chip SRAM (shared memory, ~100–228 KB per SM), computing partial softmax results and accumulating the final output without ever materializing the full N×N matrix. It does the same FLOPs as standard attention (still O(N²)) and gives the same result up to rounding; what changes is memory traffic. On Jetson AGX Orin the "slow memory" is 204.8 GB/s LPDDR5 shared with the CPU, so avoiding N×N round trips matters even more. The update rule is the online softmax from §3.

Versions (as of Oct 2026): FlashAttention-2 (2023) improved work partitioning and is the Flash backend inside PyTorch's scaled_dot_product_attention; FlashAttention-3 (2024) targets Hopper (H100) with asynchronous Tensor Core/TMA pipelines and FP8; FlashAttention-4 (2026) targets Blackwell (B200). The tiling + online-softmax idea is the same in all of them; see References.

"""
Minimal Transformer Implementation (decoder-only, GPT-style)
Run: python transformer.py

This is a DECODER-ONLY (GPT-2-style) causal language model built from the
blocks of "Attention Is All You Need" (Vaswani et al., 2017). It is NOT the
paper's encoder-decoder model. Differences from the 2017 paper:
  - decoder only: no encoder and no cross-attention
  - pre-LayerNorm + a final LayerNorm   (paper: post-LN, x = LN(x + Sublayer(x)))
  - GELU in the FFN                     (paper: ReLU)
  - learned positional embeddings       (paper: sinusoidal; learned PE was an ablation)
  - no sqrt(d_model) scaling of the token embedding (GPT-2 convention; the paper
    multiplies by sqrt(d_model) and pairs it with sinusoidal PE)
  - no biases in the attention projections, GPT-2 init (normal, std 0.02)
Shared with the paper: scaled dot-product multi-head attention, the
position-wise FFN with d_ff = 4*d, residual connections, and tying the
embedding and output (LM-head) weights (paper Sec. 3.4).

This implementation prioritizes clarity over efficiency.
For production, use F.scaled_dot_product_attention / HuggingFace / TensorRT-LLM.

References:
- Paper: https://arxiv.org/abs/1706.03762 (Attention Is All You Need)
- PyTorch: https://pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html
"""

import torch
import torch.nn as nn
import torch.nn.functional as F


class MultiHeadAttention(nn.Module):
    """
    Multi-Head Attention mechanism.

    Args:
        d_model: Hidden dimension (embedding size)
        n_heads: Number of attention heads
        dropout: Dropout probability

    Shapes:
        Input:  [B, N, d_model]
        mask:   bool tensor broadcastable to [B, h, N, N].
                True = this query MAY attend to this key.
                Same convention as the bool attn_mask of F.scaled_dot_product_attention,
                but the OPPOSITE of nn.MultiheadAttention / nn.Transformer, where
                True (or -inf) means "blocked". A row with no True entry gives NaN.
        Output: [B, N, d_model]

    Reference: https://pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention.html
    """

    def __init__(self, d_model: int, n_heads: int, dropout: float = 0.1):
        super().__init__()
        assert d_model % n_heads == 0, "d_model must be divisible by n_heads"

        self.d_model = d_model
        self.n_heads = n_heads
        self.d_k = d_model // n_heads  # Dimension per head
        self.scale = self.d_k ** -0.5   # 1/sqrt(d_k)

        # Linear projections for Q, K, V
        # Reference: https://pytorch.org/docs/stable/generated/torch.nn.Linear.html
        self.W_q = nn.Linear(d_model, d_model, bias=False)
        self.W_k = nn.Linear(d_model, d_model, bias=False)
        self.W_v = nn.Linear(d_model, d_model, bias=False)
        self.W_o = nn.Linear(d_model, d_model, bias=False)

        self.dropout = nn.Dropout(dropout)
        self.last_attn = None  # attention weights of the last call (for inspection/demos)

    def forward(self, x: torch.Tensor, mask: torch.Tensor = None) -> torch.Tensor:
        B, N, _ = x.shape

        # Project to Q, K, V
        # Each: [B, N, d_model] @ [d_model, d_model] -> [B, N, d_model]
        # GPU: cuBLAS GEMM kernel
        Q = self.W_q(x)
        K = self.W_k(x)
        V = self.W_v(x)

        # Reshape for multi-head attention
        # [B, N, d_model] -> [B, N, n_heads, d_k] -> [B, n_heads, N, d_k]
        Q = Q.view(B, N, self.n_heads, self.d_k).transpose(1, 2)
        K = K.view(B, N, self.n_heads, self.d_k).transpose(1, 2)
        V = V.view(B, N, self.n_heads, self.d_k).transpose(1, 2)

        # Compute attention scores
        # [B, h, N, d_k] @ [B, h, d_k, N] -> [B, h, N, N]
        # This is O(N²) memory - the bottleneck!
        # GPU: cuBLAS batched GEMM (one small GEMM per (batch, head))
        scores = torch.matmul(Q, K.transpose(-2, -1)) * self.scale

        # Apply mask (for causal attention): blocked positions get -inf,
        # so exp(-inf) = 0 after the softmax.
        if mask is not None:
            assert mask.dtype == torch.bool, "mask must be bool, True = may attend"
            scores = scores.masked_fill(~mask, float('-inf'))

        # Softmax and dropout
        # Reference: https://pytorch.org/docs/stable/generated/torch.nn.functional.softmax.html
        attn_weights = F.softmax(scores, dim=-1)
        self.last_attn = attn_weights.detach()
        attn_weights = self.dropout(attn_weights)

        # Apply attention to values
        # [B, h, N, N] @ [B, h, N, d_k] -> [B, h, N, d_k]
        context = torch.matmul(attn_weights, V)

        # Reshape back
        # [B, h, N, d_k] -> [B, N, h, d_k] -> [B, N, d_model]
        context = context.transpose(1, 2).contiguous().view(B, N, self.d_model)

        # Output projection
        return self.W_o(context)


class FeedForward(nn.Module):
    """
    Position-wise Feed-Forward Network.

    FFN(x) = Linear2(GELU(Linear1(x)))      (the 2017 paper uses ReLU)

    Holds ~2/3 of each block's parameters (8d² of 12d², ignoring biases).

    Shapes:
        Input:  [B, N, d_model]
        Output: [B, N, d_model]

    Reference: https://pytorch.org/docs/stable/generated/torch.nn.GELU.html
    """

    def __init__(self, d_model: int, d_ff: int = None, dropout: float = 0.1):
        super().__init__()
        d_ff = d_ff or 4 * d_model  # Default: 4x expansion

        self.linear1 = nn.Linear(d_model, d_ff)
        self.linear2 = nn.Linear(d_ff, d_model)
        self.dropout = nn.Dropout(dropout)
        self.activation = nn.GELU()

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # [B, N, d] -> [B, N, d_ff] -> [B, N, d]
        x = self.linear1(x)      # GPU: cuBLAS GEMM
        x = self.activation(x)   # GPU: Elementwise kernel
        x = self.dropout(x)
        x = self.linear2(x)      # GPU: cuBLAS GEMM
        return x


class TransformerBlock(nn.Module):
    """
    Single Transformer block with pre-normalization (GPT-2 style).

    Structure:
        x = x + Attention(LayerNorm(x))
        x = x + FFN(LayerNorm(x))
    (The 2017 paper uses post-norm: x = LN(x + Sublayer(x)).)

    Reference: https://pytorch.org/docs/stable/generated/torch.nn.LayerNorm.html
    """

    def __init__(self, d_model: int, n_heads: int, d_ff: int = None, dropout: float = 0.1):
        super().__init__()

        self.norm1 = nn.LayerNorm(d_model)
        self.attn = MultiHeadAttention(d_model, n_heads, dropout)

        self.norm2 = nn.LayerNorm(d_model)
        self.ffn = FeedForward(d_model, d_ff, dropout)

        self.dropout = nn.Dropout(dropout)

    def forward(self, x: torch.Tensor, mask: torch.Tensor = None) -> torch.Tensor:
        # Pre-norm + residual for attention
        x = x + self.dropout(self.attn(self.norm1(x), mask))

        # Pre-norm + residual for FFN
        x = x + self.dropout(self.ffn(self.norm2(x)))

        return x


class Transformer(nn.Module):
    """
    Complete decoder-only Transformer language model.

    Args:
        vocab_size:   Size of vocabulary (V)
        d_model:      Hidden dimension (d)
        n_heads:      Number of attention heads (h)
        n_layers:     Number of transformer blocks (L)
        d_ff:         Feed-forward hidden dimension (d_ff, default 4*d)
        max_seq_len:  Maximum sequence length (N_max)
        dropout:      Dropout probability

    Shapes:
        Input:  [B, N] token ids
        Output: [B, N, V] logits (row i = scores for the token at position i+1)

    Reference: https://pytorch.org/docs/stable/generated/torch.nn.Embedding.html
    """

    def __init__(
        self,
        vocab_size: int,
        d_model: int = 512,
        n_heads: int = 8,
        n_layers: int = 6,
        d_ff: int = None,
        max_seq_len: int = 512,
        dropout: float = 0.1
    ):
        super().__init__()

        self.d_model = d_model
        self.n_layers = n_layers

        # Token and position embeddings
        self.token_emb = nn.Embedding(vocab_size, d_model)
        self.pos_emb = nn.Embedding(max_seq_len, d_model)
        self.dropout = nn.Dropout(dropout)

        # Transformer blocks
        self.layers = nn.ModuleList([
            TransformerBlock(d_model, n_heads, d_ff, dropout)
            for _ in range(n_layers)
        ])

        # Final layer norm
        self.norm = nn.LayerNorm(d_model)

        # Output projection to vocabulary (the "LM head")
        self.output = nn.Linear(d_model, vocab_size, bias=False)

        # Tie weights with token embeddings (common practice)
        self.output.weight = self.token_emb.weight

        # Initialize weights
        self.apply(self._init_weights)

    def _init_weights(self, module):
        if isinstance(module, nn.Linear):
            torch.nn.init.normal_(module.weight, mean=0.0, std=0.02)
            if module.bias is not None:
                torch.nn.init.zeros_(module.bias)
        elif isinstance(module, nn.Embedding):
            torch.nn.init.normal_(module.weight, mean=0.0, std=0.02)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B, N = x.shape
        assert N <= self.pos_emb.num_embeddings, (
            f"sequence length {N} > max_seq_len {self.pos_emb.num_embeddings} "
            "(learned positional embeddings cannot extrapolate)")

        # Causal mask: True = may attend. Query i sees keys 0..i (lower triangle).
        mask = torch.tril(torch.ones(N, N, dtype=torch.bool, device=x.device))

        # Embeddings: row lookup in the [V, d] table + a learned position vector.
        # GPT-2 style: no sqrt(d_model) scaling (see module docstring).
        positions = torch.arange(N, device=x.device).unsqueeze(0)
        x = self.token_emb(x)
        x = x + self.pos_emb(positions)
        x = self.dropout(x)

        # Transformer layers
        for layer in self.layers:
            x = layer(x, mask)

        # Output
        x = self.norm(x)
        logits = self.output(x)

        return logits

    def count_parameters(self) -> int:
        """Count total trainable parameters (tied weights counted once)."""
        return sum(p.numel() for p in self.parameters() if p.requires_grad)

def compute_flops(B: int, N: int, d: int, h: int, d_ff: int, L: int, V: int = 0) -> dict:
    """
    FLOPs of one forward pass over N tokens (2 FLOPs per multiply-accumulate).

    Counts the matmuls of the L blocks and the LM head (2*B*N*d*V; pass V=0 to
    skip it), plus a 5*h*N² softmax estimate. Ignores LayerNorm, GELU, residual
    adds, the embedding gather, and the ~2x saving a causal kernel can get by
    skipping masked scores.

    All keys except 'per_layer' are summed over the L layers;
    'per_layer' is ONE layer (softmax included, LM head excluded).
    """
    # Per layer
    qkv = 6 * B * N * d * d
    qkt = 2 * B * N * N * d
    softmax = 5 * B * h * N * N
    av = 2 * B * N * N * d
    out_proj = 2 * B * N * d * d
    ffn = 4 * B * N * d * d_ff

    per_layer = qkv + qkt + softmax + av + out_proj + ffn
    lm_head = 2 * B * N * d * V
    total = L * per_layer + lm_head

    return {
        'qkv_projection': qkv * L,
        'qk_transpose': qkt * L,
        'softmax': softmax * L,
        'attn_v': av * L,
        'out_projection': out_proj * L,
        'ffn': ffn * L,
        'lm_head': lm_head,
        'per_layer': per_layer,
        'total': total
    }


def compute_memory(B: int, N: int, d: int, h: int, dtype_bytes: int = 4) -> dict:
    """
    Memory of ONE layer, in bytes.
    attention_scores: the naive [B, h, N, N] score matrix. At inference it is
                      freed before the next layer runs; FlashAttention never stores it.
    kv_cache:         K and V for N tokens with classic multi-head attention
                      (with grouped-query attention, multiply by n_kv_heads / h).
    """
    return {
        'attention_scores': B * h * N * N * dtype_bytes,
        'kv_cache': 2 * B * N * d * dtype_bytes,
        'activations': B * N * d * dtype_bytes,
    }


def format_number(n: float) -> str:
    """Format large numbers with K/M/G/T/P suffixes (powers of 1000)."""
    for div, suffix in ((1e15, "P"), (1e12, "T"), (1e9, "G"), (1e6, "M"), (1e3, "K")):
        if abs(n) >= div:
            return f"{n/div:.2f}{suffix}"
    return f"{n:.0f}"


def format_bytes(b: float) -> str:
    """Format bytes with binary units (KiB/MiB/GiB/TiB, powers of 1024)."""
    for div, suffix in ((2**40, "TiB"), (2**30, "GiB"), (2**20, "MiB"), (2**10, "KiB")):
        if b >= div:
            return f"{b/div:.2f} {suffix}"
    return f"{b:.0f} B"

8 Recap, Self-check & Exercises

Key takeaways

  • A decoder-only transformer is: embed → L × [x += Attn(LN(x)); x += FFN(LN(x))] → LN → logits. The shape stays [B, N, d] all the way through the stack.
  • Attention is a soft dictionary lookup: weights = softmax(q·Kᵀ/√d_k), output = weights·V. Multi-head = h independent lookups on d_k-sized slices, at the same FLOPs as one big head.
  • Attention mixes information across tokens; the FFN transforms each token on its own and holds about 2/3 of each block's parameters.
  • The causal mask turns one forward pass into N next-token predictions, and guarantees that past keys and values never change. That is what makes the KV-cache valid.
  • Prefill (many rows per weight read) is compute-bound; decode (one row) is memory-bound. On Jetson Orin, tokens/s ≲ DRAM bandwidth ÷ weight bytes.
  • Scores cost O(N²) FLOPs and, naively, O(N²) memory. FlashAttention removes the N×N memory and its DRAM traffic, not the FLOPs.
  • KV-cache bytes per sequence = 2 · L · N · n_kv_heads · d_k · bytes per value. GQA/MQA and KV-cache quantization are the main ways to shrink it at the edge.

Self-check

Try each question before opening the answer.

1. d = 4096 and h = 32. What is d_k, and what is the shape of the attention-score tensor for B = 2, N = 128?

Answer

d_k = 4096 / 32 = 128. Scores are [B, h, N, N] = [2, 32, 128, 128].

2. You double the sequence length N. By how much do the QKV-projection FLOPs and the QKᵀ FLOPs grow?

Answer

QKV projection is 6·B·N·d², linear in N: 2×. QKᵀ is 2·B·N²·d, quadratic: 4×.

3. Why can K and V be cached during generation, and why is Q not cached?

Answer

With a causal mask, a past token never attends to later tokens, so its K and V (in every layer) are fixed once computed, and every future query reads them. A query is only used to produce its own token's output, which is already done, so old queries are never needed again.

4. Llama 2 7B has L = 32, d = 4096 and plain multi-head attention (32 K/V heads of 128). In FP16, how big is its KV-cache per token, and for a 4096-token context? How would 8 K/V heads (GQA, as in Llama 3 8B) change that?

Answer

2 (K and V) × 32 layers × 4096 × 2 bytes = 524,288 B = 512 KiB per token, so 2 GiB for 4096 tokens, per sequence. With 8 K/V heads: 2 × 32 × 8 × 128 × 2 B = 128 KiB per token, 512 MiB for 4096 tokens: 4× smaller.

5. Without the 1/√d_k factor, what happens when the head size goes from d_k = 64 to d_k = 512?

Answer

For random unit-variance q and k, the score std is √d_k: it grows from 8 to about 22.6. The softmax becomes almost one-hot, so one key gets nearly all the weight and the gradients for the others vanish. Scaling keeps the std near 1 for any d_k.

6. A 7B-parameter FP16 model decodes at batch 1 on a Jetson AGX Orin (204.8 GB/s, ≈42.5 dense FP16 TFLOPS). Is the GPU compute-saturated? What is the upper bound on tokens/s, and what would 4-bit weights do?

Answer

No. Each decode GEMM has arithmetic intensity ≈ 1 FLOP/byte, far below the ridge of ≈ 208, so the Tensor Cores are mostly idle. Every token streams ≈ 14 GB of weights: at most 204.8 / 14 ≈ 15 tokens/s. 4-bit weights (≈ 3.5 GB) raise the ceiling about 4×, to ≈ 58 tokens/s (before KV-cache reads and other overheads).

7. What does FlashAttention change: the FLOPs, the extra memory, the DRAM traffic, the result?

Answer

FLOPs: the same (still O(N²)). Extra memory: O(N²) → O(N) (only per-row softmax statistics). DRAM traffic: much lower, Θ(N²d²/M) instead of Θ(Nd + N²). Result: identical up to floating-point rounding; it is exact attention, not an approximation.

8. In a bidirectional encoder with no positional encoding, does "dog" get a different output vector in "dog bites man" and "man bites dog"?

Answer

No. Without positions and without a mask, attention treats the input as a set: permuting the tokens only permutes the outputs. That is why positional information (learned, sinusoidal or RoPE) is added.

9. A VLM cross-attends from 100 text tokens to 576 image-patch tokens. What is the per-head score shape, and is there a causal mask?

Answer

[100, 576] (queries × keys), and no causal mask: every text token may look at every patch. Queries come from the text, keys and values from the image.

10. Roughly how many parameters does Transformer(vocab_size=50257, d_model=768, n_heads=12, n_layers=12, max_seq_len=1024) have?

Answer

About 12 layers × 12d² ≈ 84.9M, plus the tied token embedding V·d ≈ 38.6M, plus positions 1024·d ≈ 0.8M, plus small biases and norms: 124,402,944 exactly (count_parameters()). That is GPT-2 Small's shape.
