Transformer, step by step

Follow 3 tokens through a GPT. One tiny model, one running example (“the cat sat”), every number shown, from text to the next word.

Before you start

Prerequisites

  • Vectors, dot products, and matrix shapes: [3 × 4] · [4 × 4] → [3 × 4]
  • What an MLP is (weights, a nonlinearity) and that it is trained by backprop
  • No transformer knowledge needed. This page is the primer for Module 1.

Time: 60–90 minutes for the 19 steps, 5 minutes to run python step_by_step.py, plus the optional videos.

What you'll learn

  • Follow one GPT forward pass number by number, with the tensor shape at every step
  • Why each piece exists: Q/K/V, the √dk scale, the causal mask, residuals, normalization, the FFN
  • How text is generated, and why the KV cache is valid
  • Count parameters, FLOPs and memory, for the toy and for a 7B-class model

The big picture

A GPT is one function: text goes in, a probability for every possible next word comes out.

Formula
p = softmax(LM_head(blockL(… block1(embed(ids)))))
embed the 3 IDs into a [3 × 4] matrix, pass it through L blocks (the shape stays [3 × 4]), map the last row to 8 scores, and turn them into 8 probabilities.
Why this shape

Predicting the next token is the only training task of a GPT. Writing text is just repeating that prediction (step 17).

Keep in mind: every block keeps the shape [tokens × d_model]. That is why blocks can be stacked 12, 32 or 96 times.

The numbers

Our toy: “the cat sat” → p(“on”) = 0.70. The weights were chosen so “on” wins; nothing here is trained.

Real models: GPT-2 small has V = 50,257, d_model = 768 and 12 blocks; our toy has V = 8, d_model = 4 and 1 block.

logits = model(ids)             # [3, 8]
probs = logits[-1].softmax(-1)  # [8], sums to 1
shape: text → [8 probs]🎬 Watch this part: 3Blue1Brown ch. 5, “Inside a transformer” (from 3:03)
1

Text → token IDs

The model never sees letters: each token is replaced by its row number in a fixed vocabulary.

Formula
ids = tokenize(“the cat sat”) = [7, 1, 6]
3 tokens in, 3 integers out; each integer is a row number in the vocabulary of size V = 8.
Why this step

A network computes with numbers, so text must become integers first. Real tokenizers (BPE) split text into sub-word pieces, so rare words still get IDs.

Without it: nothing to compute with. With whole words only, every unseen word would be “unknown”.

The numbers

vocab = [“.”, “cat”, “dog”, “mat”, “on”, “ran”, “sat”, “the”] (alphabetical, IDs 0–7).

“the” → 7, “cat” → 1, “sat” → 6. GPT-2's real vocabulary has 50,257 tokens.

vocab = ". cat dog mat on ran sat the".split()
ids = torch.tensor([vocab.index(w) for w in
                    "the cat sat".split()])  # [7, 1, 6]
shape: [3 token IDs]
2

Embedding = picking rows from a table

Each ID picks one row of a learned table E; that row is the token's starting vector.

Formula
tok = E[ids] = onehot(ids) · E
E is [8 × 4], one row per vocabulary word. Picking rows 7, 1, 6 gives tok [3 × 4]. It equals the [3 × 8] one-hot matrix times E.
Why this step

Vectors have geometry: training can move words that behave alike (“cat”, “dog”) close together, and the dot products of later steps can measure that.

Without it: an ID like 7 has no meaning to multiply with.

The numbers
tok[the] = E[7] = [−0.2, −0.8, −0.3, −0.4]

E is a learned weight (purple). In GPT-2 small it is [50,257 × 768], about 38.6 M numbers.

tok = E[ids]          # [3, 4]
# same as nn.Embedding(8, 4) with weight E
shape: [3 tokens × 4 dims]🎬 Watch this part: 3Blue1Brown ch. 5, “Word embeddings” (from 12:27)
3

Adding position information

Add a learned “position vector” to each token, so the model can tell “the cat sat” from “sat the cat”.

Formula
x = tok + Ppos[0:3]
the position table Ppos (P in the code) is a learned [8 × 4] table, one row per position (max length 8). Row i of Ppos is added to the token at position i; x is [3 × 4].
Why this step

Attention (steps 5–10) weighs tokens by what they contain, not by where they are.

Without it: in the first block a token sees the tokens before it as an unordered bag of words; it cannot tell whether “dog” came before or after “bites”. Modern models (Llama, Qwen) use RoPE instead: they rotate q and k by an angle that depends on the position, so scores depend on the distance between tokens.

The numbers
x[the] = [−0.2, −0.8, −0.3, −0.4] + [−0.1, 0.2, 0.4, −0.3] = [−0.3, −0.6, 0.1, −0.7]

x is exact (sums of 1-decimal numbers). It is the input to the block.

x = E[ids] + P[:3]    # [3, 4]
shape: [3 tokens × 4 dims]
4

Matrix-multiply refresher (hover the cells)

Every output number of a matrix multiply is one dot product: a row of the left matrix with a column of the right one.

Formula
Q = x̂ WQ, Q[i, j] = Σk x̂[i, k] · WQ[k, j]
x̂ [3 × 4] times WQ [4 × 4] gives Q [3 × 4]. Cell (i, j) is the dot product of token i's row with column j of WQ.
Why this step

A linear layer is “each token's vector times the same weight matrix”. Stacking the 3 tokens as rows does all of them in one multiply. Matmuls are almost all the work in a transformer.

About x̂: the block first normalizes x (pre-norm); step 13 shows how. For now, x̂ is x with each row rescaled.

The numbers
x[sat] = [−0.7, 0.5, 0.7, 0.1]
x̂[sat] = [−1.59, 0.65, 1.03, −0.09] (mean 0, spread 1)

Count the work: 3 rows × 4 columns × 4 multiply-adds = 48 multiply-adds = 96 FLOPs.

xh = F.layer_norm(x, (4,))  # [3, 4], step 13
Q = xh @ W_Q    # [3, 4] @ [4, 4] -> [3, 4]
# nn.Linear(4, 4)(x) computes x @ weight.T
shape: [3 × 4] · [4 × 4] → [3 × 4]🎬 Watch this part: Karpathy, “matrix multiply as weighted aggregation” (from 47:11)
5

Q, K, V: three views of every token

Each token makes three vectors: a query (“what am I looking for?”), a key (“what do I contain?”) and a value (“what do I offer if picked?”).

Formula
Q = x̂ WQ, K = x̂ WK, V = x̂ WV
the same x̂ [3 × 4] times three different [4 × 4] weight matrices gives three [3 × 4] matrices: one query, key and value row per token.
Why this step

What a token is looking for is different from what it contains. Separate learned matrices let the model learn these roles separately.

Without it (using x̂ for Q, K and V): after normalization (with γ = 1, as here) every x̂ has the same length, so each token's best match would always be itself.

The numbers
WK [4 × 4]
WV [4 × 4]

WQ is in step 4. Each projection is 48 multiply-adds.

Q = xh @ W_Q        # [3, 4] each
K = xh @ W_K
V = xh @ W_V
shape: Q, K, V: [3 × 4] each
6

Scores = Q · Kᵀ

A score says how well query i matches key j: the dot product is large when the two vectors point the same way.

Formula
S = Qh Khᵀ, S[i, j] = qi · kj
for one head, Qh is [3 × 2] and Khᵀ is [2 × 3], so S is [3 × 3]: row i is query token i, column j is key token j.
Why this step

The model needs a number for “how relevant is token j to token i”. A dot product is cheap, and one matmul gives all 9 pairs at once.

Without it: no way to decide which earlier tokens matter. Cost: S has N × N entries, so it grows with the square of the length.

The numbers
score(sat → cat) = qsat · kcat = 1.31 × 1.03 + 0.51 × (−0.45) ≈ 1.11
head 1 scores [3 × 3]

(≈: the shown q and k are rounded; the exact sum is 1.11.)

S = Q[:, 0:2] @ K[:, 0:2].T   # head 0: [3, 3]
shape: scores: [3 × 3] per head🎬 Watch this part: 3Blue1Brown ch. 6, “The attention pattern” (from 4:29)
7

Scale by √dk

Divide the scores by √dk so they stay in a range where softmax still gives smooth weights.

head size: scale:
Formula
S′ = S / √dk (√2 = 1.41)
divide every score by the square root of the head size dk = 2. The shape stays [3 × 3].
Why this step

If q and k have dk independent entries with variance 1, then q · k is a sum of dk terms with variance dk: its spread grows like √dk. Dividing by √dk brings the spread back to about 1, whatever the head size.

Without it: for big heads the softmax saturates to one-hot, the other weights get almost zero gradient, and training stalls.

The numbers
1.11 / 1.41 = 0.79

With dk = 128 the same row would have raw scores about √(128/2) = 8 times bigger: [−11.06, 8.92, −9.77]. Divided by √128 = 11.31, they give exactly the toy's scaled row back.

head 0, S / √2 [3 × 3]
S = S / math.sqrt(2)          # d_k = 2
shape: [3 × 3] per head
8

Causal mask: no peeking at the future

A token may only look at itself and earlier tokens, so every score to a later token is set to −∞.

mask:
Formula
S′[i, j] = −∞ if j > i
in row i (query token i), every column j right of the diagonal (a later token) becomes minus infinity, so its weight after the softmax is exp(−∞) = 0.
Why this step

Training predicts token i+1 from tokens 0…i, for every position in one pass. If token i could see token i+1, it would just copy the answer.

Without it: training “cheats”, and at generation time the future does not exist yet, so the model would meet inputs unlike anything it trained on. The mask also makes the KV cache valid (step 17).

The numbers

Row “the” can only see itself: its masked row is [−0.10, −∞, −∞], so its weights are [1, 0, 0]. That is why the first row of every causal attention matrix is [1, 0, 0].

Mask off: “the” would put 0.67 of its attention on “cat” and “sat”, which come after it.

mask = torch.tril(torch.ones(3, 3)).bool()
S = S.masked_fill(~mask, float("-inf"))
shape: [3 × 3] per head🎬 Watch this part: 3Blue1Brown ch. 6, “Masking” (from 11:08)
9

Softmax: scores become weights

Softmax turns each row of scores into positive weights that add up to 1: a “soft” choice of which tokens to read.

Formula
A[i, j] = exp(S′[i, j]) / Σj′ exp(S′[i, j′])
exponentiate each score in row i, then divide by the row's total. A is [3 × 3]; every row is positive and sums to 1.
Why this step

Exponentiating makes everything positive and lets big scores dominate; dividing by the sum makes the weights an average. Unlike argmax it is smooth, so gradients flow to every score.

Without it: weights could be negative or huge, and the output's scale would change with the number of tokens.

The numbers
exp(−0.98), exp(0.79), exp(−0.86) = 0.38, 2.20, 0.42; sum = 3.00
weights = exp / sum = 0.13, 0.73, 0.14
head 0, A [3 × 3]
head 1, A [3 × 3]
A = torch.softmax(S, dim=-1)  # rows sum to 1
shape: weights A: [3 × 3], rows sum to 1
10

Weighted sum of the values

Each token's output is a blend of the value vectors, mixed with its attention weights.

Formula
Oh = A Vh, oi = Σj A[i, j] · vj
A [3 × 3] times Vh [3 × 2] gives Oh [3 × 2]: output i is a weighted average of the value rows, with row i of A as the weights.
Why this step

This is the only place in the whole model where a token reads information from other tokens. Steps 6–9 only decided how much to read from each.

Without it: each token would be processed alone and could never use its context.

The numbers
osat = 0.13·[0.80, 0.39] + 0.73·[2.16, −0.24] + 0.14·[−1.34, 0.37] ≈ [1.50, −0.08]
head 0, O0 [3 × 2]
head 1, O1 [3 × 2]
O = A @ V[:, 0:2]   # [3, 3] @ [3, 2] -> [3, 2]
shape: Oh: [3 × 2] per head🎬 Watch this part: 3Blue1Brown ch. 6, “Values” (from 13:10)
11

Multi-head: several lookups side by side

Split the 4 dims into 2 heads of 2, run steps 6–10 in each head separately, glue the outputs back together and mix them with WO.

Formula
MHA(x̂) = [O0 | O1] WO
run steps 6–10 once per head on its own 2 columns, put the two [3 × 2] outputs side by side ([3 × 4]), then multiply by WO [4 × 4].
Why this step

One softmax row can only express one blend. With several heads a token can read different things at once (for example, one head the subject, another the previous word). It costs the same FLOPs as one head of size 4.

Without WO: each head's result would stay locked in its own 2 columns.

The numbers
WO [4 × 4]
attn_out = concat · WO [3 × 4]

Checked in step_by_step.py: equal to F.scaled_dot_product_attention(…, is_causal=True).

q, k, v = [t.view(3, 2, 2).transpose(0, 1) for t in (Q, K, V)]
o = F.scaled_dot_product_attention(q, k, v, is_causal=True)
attn_out = o.transpose(0, 1).reshape(3, 4) @ W_O  # [3, 4]
shape: concat [3 × 4] → WO → [3 × 4]🎬 Watch this part: 3Blue1Brown ch. 6, “Multiple heads” (from 19:19)
12

Residual connection: keep the original, add an edit

The attention result is not a replacement for x: it is an edit that gets added to x.

Formula
h = x + MHA(LN(x))
the attention output [3 × 4] is added, element by element, to the block's own input x [3 × 4].
Why this step

The “+ x” path is a highway: the gradient reaches early layers through it unchanged (∂h/∂x = I + …), so stacks of 50–100 blocks still train. Each block only has to learn a small change.

Without it: deep stacks become very hard to train, and every block would have to re-create everything it does not change.

The numbers
h[sat] = [−0.7, 0.5, 0.7, 0.1] + [−0.15, −0.99, 2.29, 0.21] = [−0.85, −0.49, 2.99, 0.31]

The running sum x → h → y is called the residual stream.

h = x + attn_out              # [3, 4]
shape: h: [3 × 4]🎬 Watch this part: Karpathy, “residual connections” (from 1:26:48)
13

LayerNorm / RMSNorm: rescale each token

Normalization shifts and rescales each token's vector to mean 0 and spread 1, so the next layer always sees numbers of a similar size.

Formula
LN(h) = γ ⊙ (h − μ) / √(σ² + ε) + β
RMSNorm(h) = γ ⊙ h / √(mean(h²) + ε)
for each token (row) separately: subtract the row mean μ, divide by the row standard deviation σ, then scale by γ and shift by β (here γ = 1, β = 0, their starting values). The shape stays [3 × 4].
Why this step

Every block adds its edit to the residual stream, so its numbers drift and grow with depth. Normalizing the input of each sub-layer keeps matmuls and softmax in a stable range.

Without it: activations and gradients blow up or shrink across layers, and training needs tiny learning rates. GPT-2 uses LayerNorm; Llama uses RMSNorm (no mean, no β), which is a bit cheaper.

The numbers
h[sat] = [−0.85, −0.49, 2.99, 0.31]
μ = 0.49, σ² = 2.26, σ = 1.50
h − μ = [−1.34, −0.98, 2.50, −0.18]
(h − μ) ÷ σ ≈ [−0.89, −0.65, 1.66, −0.12]
RMSNorm: rms = 1.58, h ÷ rms ≈ [−0.54, −0.31, 1.89, 0.19]
ĥ = LayerNorm(h) [3 × 4], the FFN's input

The same operation made x̂ from x in step 4.

mu = h.mean(-1, keepdim=True)
var = h.var(-1, unbiased=False, keepdim=True)
hh = (h - mu) / (var + 1e-5).sqrt()  # F.layer_norm(h, (4,))
shape: ĥ: [3 × 4]🎬 Watch this part: Karpathy, “layernorm” (from 1:32:51)
14

Feed-forward network (FFN): think about each token alone

A small MLP runs on every token separately: widen to 8 numbers, zero out the negatives, shrink back to 4.

Formula
FFN(ĥ) = ReLU(ĥ W1) W2
ĥ [3 × 4] times W1 [4 × 8] gives u [3 × 8]; ReLU sets negatives to 0; times W2 [8 × 4] gives back [3 × 4]. Each row is processed on its own.
Why this step

Attention only moves and averages information. The FFN transforms it: in big models it holds about 2/3 of each block's weights and is thought to store much of the learned knowledge.

Why the nonlinearity: without ReLU, ĥ W1 W2 = ĥ (W1W2), a single [4 × 4] matrix, and the 8-wide layer adds nothing. GPT-2 uses GELU (a smooth ReLU); Llama uses SwiGLU.

The numbers
W1 [4 × 8]
W2 [8 × 4]
f = FFN(ĥ) [3 × 4], all three tokens
f = torch.relu(hh @ W1) @ W2  # [3,4]->[3,8]->[3,4]
shape: [3 × 4] → [3 × 8] → [3 × 4]🎬 Watch this part: 3Blue1Brown ch. 7, “Inside a multilayer perceptron” (from 6:07)
15

One full block, then stack L of them

A block is two “normalize, compute, add back” steps: attention, then FFN. The output has the input's shape, so blocks stack.

Formula
h = x + MHA(LN1(x))
y = h + FFN(LN2(h))
two sub-layers, each “normalize, compute, add back”. Input x and output y are both [3 × 4], so x → block 1 → block 2 → … → block L works.
Why this order

This is the pre-norm block of GPT-2 and of transformer.py: the norm sits inside the side branch, so the residual highway stays a clean sum.

Stacking: GPT-2 small has 12 blocks, Llama 2 7B has 32, GPT-3 175B has 96. Each has its own weights.

The numbers
y[sat] = h[sat] + f[sat] = [−0.85, −0.49, 2.99, 0.31] + [−0.18, −0.08, −0.60, 0.01] ≈ [−1.02, −0.57, 2.39, 0.32]
block output y [3 × 4]
h = x + attn(F.layer_norm(x, (4,)))   # steps 4-12
y = h + ffn(F.layer_norm(h, (4,)))    # steps 13-14
# L blocks: repeat with new weights, x = y
shape: y: [3 × 4] (same as x)
16

Final norm → LM head → next token

The last token's vector is scored against every vocabulary word; softmax turns the 8 scores into probabilities.

Formula
logits = LNf(y) U, p = softmax(logitslast / T)
normalize y [3 × 4], multiply by the LM head U [4 × 8]: one score per vocabulary word for every position ([3 × 8]). The last row predicts the next token; T is the temperature (T = 1 leaves it unchanged).
Why this step

We need one probability per vocabulary word. Each logit is a dot product of the final vector with that word's column of U. GPT-2 and transformer.py reuse the embedding table here (U = Eᵀ); our toy has its own U.

Greedy vs sampling: greedy always takes the top word (repetitive); sampling draws from p (varied). Temperature, top-k and top-p shape p before sampling.

The numbers
ŷ = LayerNorm(y) [3 × 4]
U, the LM head [4 × 8]
logits [3 × 8]: row i predicts token i+1

p(on) = 0.97 at T = 0.5, 0.70 at T = 1, 0.38 at T = 2.

logits = F.layer_norm(y, (4,)) @ U          # [3, 8]
probs = torch.softmax(logits[-1] / T, -1)   # [8]
next_id = probs.argmax()  # or torch.multinomial(probs, 1)
shape: logits [3 × 8] → last row → [8 probs]🎬 Watch this part: 3Blue1Brown ch. 5, “Unembedding” and “Softmax with temperature” (from 20:22)

Generating text: the loop and the KV cache

Pick a token, append it, run again. Old tokens' keys and values never change, so we keep them in a cache and push only the new token through.

Formula
repeat: p = model(ids); t = pick(p); ids = ids + [t]
run the model, pick a token, append it, repeat. With a KV cache each step sends only the new token through the block: q, k, v are [1 × 4], and the K and V caches grow from [3 × 4] to [4 × 4] to [5 × 4].
Why K and V can be cached, but not Q

Thanks to the causal mask, a past token never looks at later tokens, so its output, and with it its K and V in every layer, never changes. Every future query reads those K, V again: compute them once, keep them.

A query is only used to make its own token's output, which is already done, so old queries are never needed again. (In our 1-block toy, K and V depend only on each token's own embedding and position; in deeper models the mask is what keeps them fixed.)

Without the cache: every step re-runs the whole prefix, so the total work grows at least with the square of the length.

The numbers

Prefill “the cat sat” → “on” (p = 0.70). Decode “on” → “the” (p = 0.66). Decode “the” → “mat” (p = 0.65).

New key of “on”: k = [0.05, 0.85, −0.62, −0.35]. The first 3 cache rows are exactly the K and V of step 5.

step_by_step.py asserts that the cached logits equal a full recompute at every step. Result: “the cat sat on the mat”.

k_cache = torch.cat([k_cache, k_new[None]])  # [t+1, 4]
v_cache = torch.cat([v_cache, v_new[None]])
w = (q_new[:2] @ k_cache[:, :2].T / 2**0.5).softmax(-1)  # head 0
shape: K, V cache: [t × 4], grows by 1 row📖 Read this part: Jay Alammar, The Illustrated GPT-2 (the section on processing one new token at a time)

Counting: parameters, FLOPs and memory

Count the weights once, and you can estimate the compute and the memory of any GPT.

Formula
params ≈ L·(4d² + 2·d·dff) + V·d
FLOPs/token ≈ 2 × params + 4·L·N·d
KV bytes/token = 2 · L · d · bytes
each block has 4d² attention weights (WQ, WK, WV, WO) and 2·d·dff FFN weights (= 8d² when dff = 4d); a forward pass does 2 FLOPs (multiply + add) per weight per token, plus attention over N context tokens; every token stores one K and one V vector of size d per layer.
Why it matters

Generating one token (at batch size 1) reads every weight once but does only about 2 FLOPs per weight, so on a GPU it is limited by memory bandwidth, not compute. Shrinking weight memory (quantization) and KV-cache memory (GQA, KV quantization, paging) is where inference optimization starts. These are explained in the full guide §2.4 and the cookbook cards b, c and e.

Next: Memory & inference efficiency cookbook and the complexity and memory sections of the full guide.

The numbers

Toy (d = 4, dff = 8, L = 1, V = 8): embedding 32 + positions 32 + attention 64 + FFN 64 + norms 24 + LM head 32 = 248 parameters. Forward pass over 3 tokens: 1104 FLOPs = 3 × 320 + 144 for attention. KV cache: 8 numbers per token.

7B-class (GPT-3 6.7B shape: d = 4096, L = 32, dff = 4d, V = 50,257, 2048 positions): 12d² = 201,326,592 per block × 32 = 6,442,450,944, + embeddings 205,852,672 + positions 8,388,608 = 6,656,692,224.

Compute: about 13.3 GFLOPs per token (+ 1.07 for attention at N = 2048). Weights in FP16: 13.3 GB. KV cache in FP16: 2 × 32 × 4096 × 2 B = 524,288 B = 512 KiB per token, 1.0 GiB at 2048 tokens, 2.0 GiB at 4096 (Llama 2 7B has the same d and L, so the same cache).

weights = (E, P, W_Q, W_K, W_V, W_O, W1, W2, U)
n_params = sum(t.numel() for t in weights) + 24  # + norms
kv_bytes_per_token = 2 * L * d * 2  # K + V, FP16

Key takeaways

  • A GPT maps token IDs to next-token probabilities: embed + position → L blocks → final norm → LM head → softmax. The shape stays [tokens × d] through every block.
  • Every linear layer is a matmul, and every output number is one dot product of a token's row with a weight column, done for all tokens at once.
  • Attention = scores q·k → ÷√dk → causal mask → softmax → weighted average of the values. It is the only place where tokens exchange information.
  • Multi-head attention runs the same lookup on separate slices of the dims, then mixes the results with WO.
  • Residuals keep the input and add an edit; normalization keeps each token's vector at a steady scale; the FFN transforms each token on its own and needs its nonlinearity.
  • Generation is a loop. Because of the causal mask, old keys and values never change, so they are cached and only the new token is computed.
  • params ≈ 12·L·d² + V·d, FLOPs per token ≈ 2 × params, KV cache = 2·L·d·bytes per token: the starting point for inference optimization.

Self-check

Try each question before opening the answer.

1. In the toy, what are the shapes of Q, of one head's score matrix, and of the logits?

Answer

Q is [3 × 4] (3 tokens × d_model). Each head's scores are [3 × 3] (query × key), and there are 2 heads. The logits are [3 × 8] (one row per position, one column per vocabulary word); only the last row is used to pick the next token.

2. Why is the first row of every causal attention matrix [1, 0, 0]?

Answer

Token 0 may only look at itself: the other scores in its row are −∞. A softmax over one finite score gives weight 1 to it and exp(−∞) = 0 to the rest.

3. A real model has dk = 128 and q, k entries with variance 1. What is the typical size (standard deviation) of a raw score, and what happens without the 1/√dk scale?

Answer

The variance of q·k is dk = 128, so the standard deviation is √128 ≈ 11.31. Softmax of numbers that far apart is almost one-hot (step 7's demo gives 0.00, 1.00, 0.00), so the other keys get almost no gradient and training stalls.

4. What goes wrong if we skip the projections and use x̂ itself as Q, K and V?

Answer

After LayerNorm (with γ = 1, as here) every x̂ has the same squared length d = 4, so by Cauchy–Schwarz x̂i·x̂j ≤ x̂i·x̂i: every token scores itself highest. The model also could not separate “what I look for” from “what I contain”, or choose what to pass on.

5. Why does the FFN need the ReLU between W1 and W2?

Answer

Without it, (ĥW1)W2 = ĥ(W1W2): two linear layers collapse into one [4 × 4] matrix, so the 8-wide hidden layer adds nothing a single linear map could not do.

6. During generation, why can K and V be cached, but not Q?

Answer

With a causal mask, a past token never attends to later tokens, so its K and V (in every layer) are fixed once computed, and every later query reads them. A query is only used to produce its own token's output, which is already done, so old queries are never needed again.

7. How many numbers does the toy's KV cache hold after “the cat sat on the” (5 tokens)? How big is the cache of the 7B-class model from step 18 for one 4096-token sequence in FP16?

Answer

Toy: 5 tokens × (4 for K + 4 for V) × 1 layer = 40 numbers (the last state of step 17). 7B-class: 2 × 32 layers × 4096 × 2 bytes = 512 KiB per token, × 4096 tokens = 2.0 GiB.

8. Most GPTs use dff = 4·d. How many parameters would the toy have with dff = 16 instead of 8?

Answer

The FFN goes from 2·4·8 = 64 to 2·4·16 = 128 weights; nothing else changes: 248 − 64 + 128 = 312.
