In plain words: patches are the "words" of an image. ViT cuts a picture into small square patches, turns each patch into a vector, and reads the row of patches with the same Transformer you met in Module 1.

⏱️ ViT in one minute

Until 2020, computer vision meant CNNs: small filters slid across the image, building up from edges to objects layer by layer. ViT asked a blunt question: what if we feed an image to the same Transformer encoder used for text? The recipe: cut a 224×224 image into a 14×14 grid of 16×16-pixel patches, turn each patch into a 768-dim vector with one matrix multiply, prepend one extra learnable [CLS] slot, add a learned position vector to every slot, run 12 standard encoder blocks over the resulting 197 tokens, and read the class out of the [CLS] slot. That's the whole model.

What's new compared with Module 1: only three things. (1) A patch front-end replaces the tokenizer and embedding table. (2) A [CLS] read-out replaces the LM head. (3) Position embeddings index a 2D grid. Everything in between (attention, FFN, LayerNorm, residuals) is the block you already know, minus the causal mask and the KV cache.

Why it matters next: a ViT (or a descendant such as SigLIP or the Qwen-VL vision tower) is the vision encoder in the VLM, VLA and robot-FM modules that follow.

2. Inference Data Flow

2.0 Why Vision Transformer? (Replacing CNNs)

In plain words: a CNN looks at an image through a small window and widens its view layer by layer. A ViT lays all the patches on the table at once and lets any patch look at any other from the very first layer.

What to notice: a CNN must stack many layers before far-apart pixels can interact; a ViT connects any two patches in its first layer.

  • ① ResNet-50 halves the resolution at each stage (224² → 112² → 56² → 28² → 14² → 7²) while the channels grow from 64 to 2048. A 3×3 conv sees only its neighbours. This built-in bias (locality, translation equivariance) is why CNNs train well on small datasets.
  • ② ViT cuts the image into 14×14 = 196 patches (4×4 drawn) and treats each patch as a token. Its bias is weak: only the patching and a shared per-token MLP. It learns the spatial layout from data, so it needs more data or pretraining.
  • ③ Self-attention is all-to-all: patch 0 (top-left) can attend directly to patch 195 (bottom-right) in layer 1.

Why ViT took over vision foundation models:

  • Global context from layer 1.
  • The same block as LLMs: shared kernels, tooling and scaling know-how, and image tokens plug straight into an LLM (Module 3).
  • It scales well with data and compute. (CNNs trained at the same scale can match it, e.g. NFNets on JFT-4B.)
🧩 Decoding the jargon

Inductive bias = assumptions wired into the architecture instead of learned from data. Estimation analogy: a Kalman filter with an accurate process model needs few measurements; one with a generic random-walk model needs far more data to track the same system. A CNN ships with a good "process model" for images. ViT ships with very little.

Locality: a pixel's meaning depends mostly on its neighbours, so a 3×3 conv looks at only 9 pixels. Translation equivariance: shift the input 10 px and the feature map shifts 10 px, because the same filter is reused at every position. Receptive field: the input region that can influence one output value. Stacked 3×3 convs grow it by ~2 px per layer, so a CNN needs depth and downsampling before distant regions can interact.

ViT's bias is weak, not zero. Cutting the image into patches assumes locality, and the FFN applies the same weights to every token. Self-attention, though, is global from layer 1: patch (0,0) can read patch (13,13) directly.

The price, in numbers (ViT paper, §4.3 / Fig. 3): pre-trained on ImageNet-1k (1.3M images), ViT-L does worse than the smaller ViT-B. On ImageNet-21k (14M) they are similar. Only with JFT-300M does the larger model pull ahead. Later recipes (DeiT, Beyer et al. 2022) closed much of the gap with heavy augmentation, but in practice you still start from a pretrained checkpoint.

2.1 High-Level Inference Pipeline

In plain words: cut, tag, mix, read out. The image is cut into patch tokens, each token is tagged with its position, 12 Transformer blocks mix the tokens, and one summary token gives the answer.

data learned weights mixing across tokens output bookkeeping

What to notice: the shape changes only at the two ends. All 12 blocks keep [197, 768]: 196 patch tokens plus one [CLS] token, each 768 numbers wide.

  • Shapes with the batch dimension B: [B,3,224,224] → [B,196,768] → [B,197,768] → 12 blocks → [B,197,768] → final LN, take x[:, 0] → [B,768] → [B,1000].
  • Patch embed: 196 patches × 768 pixel values each (16·16·3) → one Linear → 196 tokens of width d = 768. The two 768s are a coincidence (§2.2).
  • [CLS]: one learnable vector placed in front of the patches. Through attention it gathers information from all patches; after the last block and the final LayerNorm it is the image's summary vector.
  • Head: 768 → 1000 classes. The paper pre-trains with an MLP head; fine-tuned checkpoints (and this code) use a single Linear.

2.2 Patch Embedding: Image → Tokens

In plain words: cut the image into tiles, unroll each tile into one long list of numbers, and run every list through the same learned matrix. Each result is one token.

What to notice: the same matrix W_patch is applied to all 196 patches, so the whole step is one matrix multiply: [196, 768] @ [768, d] = [196, d]. Patch p₀ is highlighted; the others go through the same path. The image holds 3 × 224 × 224 = 150,528 values; patches are numbered row by row, index = 14·row + col (p₀ top-left, p₁₉₅ bottom-right).

Patchify shapes, step by step
Intuition
Tiles in, tokens out: every P×P tile becomes one row of numbers, and one shared matrix turns each row into a d-wide token.
N = (H / P) · (W / P)
Xp : [N, P²·C]
Z = Xp · E + b   : [N, d]
Read it aloud
An H×W image with C colour channels, cut into P×P tiles, gives N tiles. Each tile becomes one row of P²·C numbers in Xp. The matrix E has P²·C rows and d columns, so Xp·E gives N tokens, each d numbers wide. For ViT-B/16: N = (224/16)² = 196, P²·C = 16·16·3 = 768, and E is [768, 768], square only by coincidence (ViT-L/16 maps the same 768 numbers to d = 1024).
Why it exists
A Transformer needs a sequence of vectors. Using every pixel as a token would give 224·224 = 50,176 tokens and about 2.5 billion attention pairs per head; 16×16 patches give 196 tokens and 38,416 pairs (65,536× fewer). The matrix E also lets the token width d be chosen independently of the patch size.
Tiny example

A grayscale 4×4 image, patch size P = 2, so (4/2)² = 4 patches of 2·2·1 = 4 values, projected to d = 2:

0 0 | 0 9
0 0 | 0 9
----+----
0 0 | 9 9
0 0 | 9 9

Patches in raster (row-major) order: p0 = [0,0,0,0], p1 = [0,9,0,9], p2 = [0,0,0,0], p3 = [9,9,9,9].
E (4×2): column 0 is a "brightness" template [¼,¼,¼,¼]; column 1 is a "left-minus-right edge" template [1,−1,1,−1].
Tokens = patches @ E: p0 → [0, 0], p1 → [4.5, −18] (the edge template fires), p2 → [0, 0], p3 → [9, 0] (bright and flat).

Two things to notice. (1) A Conv2d(1, 2, kernel_size=2, stride=2) whose two kernels are those columns reshaped to 2×2 produces exactly these numbers. (2) p0 and p2 give identical tokens: only the position embedding (§2.3) can tell them apart. In ViT-B/16, E has 768 columns; each column, reshaped to 16×16×3, is a learned template, and the ViT paper (Fig. 7, left) shows their principal components look like smooth colour/frequency basis functions, much like first-layer CNN filters.

Code

x = proj(img)                                     # [B, d, 14, 14]
x = x.flatten(2).transpose(1, 2)                  # [B, 196, d], row-major patch order

2.3 Position Embeddings: Where is Each Patch?

In plain words: attention is like a meeting where nobody has a seat number. It hears what every patch says but not where the patch sits. A position embedding stamps each patch with its seat number.

What to notice: without positions, attention treats the patches as an unordered set: shuffle them and the patch outputs shuffle the same way, while the [CLS] output does not change at all. Adding a learned vector Ei (purple outline) to slot i makes the same patch content at a different place a different input.

The input sequence: [CLS] + patches + positions
Intuition
Put one empty "summary" slot in front of the patches, then add a learned address vector to every slot.
z0 = [ xcls ; Xp·E ] + Epos
[1, d] stacked on [196, d] → [197, d],  Epos : [197, d]
Read it aloud
The starting sequence z-zero is the class token stacked on top of the 196 patch tokens, plus one learned position vector per row. Row 0 belongs to [CLS]; row 1 is the top-left patch (0, 0) and row 196 the bottom-right patch (13, 13).
Why it exists
Attention and the FFN are permutation-equivariant, so Epos is the model's only source of "where". [CLS] gives the classifier one vector that must collect its content from the patches through attention (the alternative, averaging the patch outputs, is discussed in §3).
Tiny example
In the 4×4 example above, p0 and p2 both became [0, 0]. They sit in rows 1 and 3. With position vectors E1 = [0.5, 0] and E3 = [0.5, 0.5]: p0 → [0.5, 0] and p2 → [0.5, 0.5]. Same content, different inputs.
Code
cls_token = nn.Parameter(torch.zeros(1, 1, 768))
pos_embed = nn.Parameter(torch.zeros(1, 197, 768))
x = torch.cat([cls_token.expand(B, -1, -1), patches], dim=1) + pos_embed   # [B, 197, 768]
Key fact
The table is one-dimensional (rows 0–196), yet after training nearby patches get similar vectors: the 2D grid is learned. Try the widget below.

What to notice: similarity is highest along the query's own row and column and fades with distance, although nothing in attention knows about rows. The learned table of the original ViT ends up with the same pattern (ViT paper, Fig. 7 centre: "closer patches tend to have more similar position embeddings"). Raise β and the head becomes a local, 3×3-conv-like filter (β = 60: ~88% of the weight in the 3×3 neighbourhood); at β = 0 it averages the whole image. ViT does not get locality for free, but each head can learn it. In β·cos, β plays the role of ‖q‖·‖k‖/√dk.

2.4 Complete ViT Block: Multi-Head Attention + FFN

In plain words: attention lets the patches talk to each other; the FFN lets each patch think on its own. A residual "highway" carries the input past both, so each block only adds a correction.

What to notice: the orange step mixes information across patches; the green step transforms each patch on its own. Each result is added back onto the blue residual stream, so the shape stays [197, 768] through all 12 blocks.

  • vs the 2017 Transformer: (1) pre-norm, LayerNorm before attention/FFN (2017 used post-norm; GPT-2 and LLaMA are pre-norm too); (2) no causal mask, every patch sees every patch; (3) GELU MLP, 4× wide (768 → 3072); (4) encoder only: no decoder, no KV cache.
  • Per-block cost (FLOPs = 2 × MACs): QKV + out-proj 8·B·T·d²; QKᵀ and A·V 4·B·T²·d (softmax O(B·h·T²)); FFN 16·B·T·d². At T = 197, d = 768 the FFN is ≈ 64% of the block and the T² terms ≈ 4%; they grow with resolution (§2.5).

You arrive here from Module 1, a decoder-only LLM that is already pre-norm with a GELU FFN. The differences that matter for inference are elsewhere:

2.5 Full Model: Where the Parameters and Compute Go

In plain words: most of the work is the FFN's two big matrix multiplies, not attention. Attention's token-pair part only takes over once the image, and so the token count, gets large.

patch embed + head QKV + output projection (weight matrices) QKᵀ and A·V (mixing across tokens) FFN (per-token compute)

What to notice: at 224 px the FFN does about two thirds of the work and the T² part of attention only 4%. At 1024 px (T = 4097, the resolution of SAM's ViT-H encoder) the T² part becomes the largest share (47%) and the total grows 37.6× (17.56 → 659.8 GMACs).

ViT-B/16 per image: 17.56 GMACs = 35.1 GFLOPs (paper tables print the GMAC number as "GFLOPs"): patch embed 0.12 GMACs (0.7%), attention over 12 layers 6.29 GMACs (35.8%, of which only 0.72 GMACs is the T² part), FFN 11.16 GMACs (63.5%). Parameters, which match count_parameters() in vit.py:

Read it aloud
Twelve times tokens times width squared, from the weight matrices (QKV 3, output projection 1, FFN 8), plus two times tokens squared times width, from QKᵀ and A·V. T is the token count (197), d the width (768).
Why it exists
It tells you what to optimize. The first term grows linearly with tokens, the second with their square. Their ratio is T/(6d), so for ViT-B the T² part only catches up with the rest at T = 6d = 4608 tokens.
Tiny example

3. Architecture Blocks (Expandable)

Patch Embedding Layer ▼

Purpose: Turn a 224×224 RGB image into a sequence of 196 patch embeddings, each a 768-dim vector. This is the moment an image "becomes" a token sequence the transformer can consume.

The trick: A Conv2d with kernel_size = stride = patch_size is mathematically identical to "cut image into non-overlapping 16×16 patches, flatten each, apply a linear projection" — but runs as one convolution instead of a reshape + copy + GEMM. Same output (vit.py checks this numerically in demo_patchify_equivalence()).

class PatchEmbed(nn.Module):
    def __init__(self, img_size=224, patch_size=16, in_chans=3, embed_dim=768):
        super().__init__()
        self.num_patches = (img_size // patch_size) ** 2    # (224/16)² = 14² = 196
        # kernel=stride=16 means each output "pixel" sees one non-overlapping 16×16 patch
        self.proj = nn.Conv2d(in_chans, embed_dim,
                              kernel_size=patch_size, stride=patch_size)

    def forward(self, x):
        # x: [B, 3, 224, 224]  — standard NCHW image tensor
        x = self.proj(x)                    # Conv2d → [B, 768, 14, 14]
        x = x.flatten(2).transpose(1, 2)    # [B, 768, 196] → [B, 196, 768] (row-major order)
        return x

Parameters: 3 × 16 × 16 × 768 + 768 (bias) = 590,592 — just 0.7% of ViT-B's 86.6M. Patch embed is tiny; the transformer layers dominate.

FLOPs: 2 × 196 × (3 × 16 × 16) × 768 = 2 × 196 × 768 × 768 ≈ 0.23 GFLOPs (= 0.116 GMACs). Treat it as a plain GEMM with M=196, N=768, K=768 — Tensor-Core friendly.

Position + CLS Token ▼

Purpose: Add two things to the patch sequence — a learnable [CLS] token that will collect global image info through self-attention, and position embeddings that tell the model where each patch came from in the 2D grid.

Why a CLS token at all? The classifier needs one vector for the whole image. [CLS] is an empty seat at the table: it carries no pixels, only a learned starting vector, so whatever it holds after L layers it must have gathered by attending to the patches. The alternative is global average pooling (GAP): average the 196 output patch tokens. The ViT paper found both work about equally well once the learning rate is tuned (App. D.3) and kept [CLS] to stay close to the text Transformer; later plain-ViT recipes often prefer GAP (Beyer et al. 2022: 80.0% with GAP vs 78.2% with [CLS] for ViT-S/16).

# In ViT __init__:
self.cls_token = nn.Parameter(torch.zeros(1, 1, embed_dim))          # [1, 1, 768] — one learnable vec
self.pos_embed = nn.Parameter(torch.zeros(1, num_patches + 1, embed_dim))  # [1, 197, 768] — one per slot
nn.init.trunc_normal_(self.pos_embed, std=0.02)                 # as in vit.py
nn.init.trunc_normal_(self.cls_token, std=0.02)

# In forward:
def forward(self, x):
    B = x.shape[0]
    x = self.patch_embed(x)                          # [B, 3, 224, 224] → [B, 196, 768]

    # Prepend the CLS token — same vector broadcast across the batch
    cls_tokens = self.cls_token.expand(B, -1, -1)   # [B, 1, 768]
    x = torch.cat([cls_tokens, x], dim=1)          # [B, 197, 768]

    # Add position info — broadcast over the batch dim (row 0 belongs to CLS)
    x = x + self.pos_embed                            # [B, 197, 768]
    return x

Note: Position embeddings are a 1D table (rows 0–196) but learn 2D spatial structure during training — adjacent patches end up with similar embeddings (see the widget in §2.3). Other models use other schemes: Swin uses a learned relative position bias; MAE and "Better plain ViT baselines" use fixed 2D sin-cos; recent backbones such as DINOv3 and the Qwen-VL vision towers use 2D RoPE. DeiT keeps ViT's learned 1D table. The ViT paper (App. D.4) found 1D, 2D and relative variants perform about the same.

Multi-Head Self-Attention (Same as LLM, minus the mask) ▼

Purpose: Let every patch look at every other patch and decide what's relevant. After this layer, each patch's embedding blends information from across the whole image.

How it splits the work: The 768-dim embedding is sliced into h=12 heads of 64 dims each. Each head computes its own Q·Kᵀ score matrix, applies softmax, and weights V independently; the outputs are concatenated and mixed by W_o. The ViT paper measured what heads do in terms of attention distance: in early layers some heads attend only to nearby patches (acting like small convolutions) while others already span the whole image, and the mean attention distance grows with depth (Fig. 7, right).

class Attention(nn.Module):
    def __init__(self, dim=768, num_heads=12):
        super().__init__()
        self.num_heads = num_heads
        self.head_dim = dim // num_heads         # 64 — each head's slice of embedding
        self.scale = self.head_dim ** -0.5    # 1/sqrt(64)=0.125, keeps softmax stable

        # One Linear for Q,K,V is faster than three — a single batched GEMM
        self.qkv = nn.Linear(dim, dim * 3)        # weight: [2304, 768] (out, in); y = x @ W.T
        self.proj = nn.Linear(dim, dim)            # output projection W_o

    def forward(self, x):
        B, N, C = x.shape                          # [B, 197, 768]: batch, tokens T, width d (timm names them N, C)

        # Project and split into Q, K, V for all heads in one shot
        qkv = self.qkv(x).reshape(B, N, 3, self.num_heads, self.head_dim)
        qkv = qkv.permute(2, 0, 3, 1, 4)    # [3, B, 12, 197, 64] → unbind QKV
        q, k, v = qkv[0], qkv[1], qkv[2]       # each: [B, 12, 197, 64]

        # Score matrix: how much does each query look at each key?
        # NO CAUSAL MASK in ViT — every patch sees every patch (bidirectional)
        attn = (q @ k.transpose(-2, -1)) * self.scale  # [B, 12, 197, 197]
        attn = attn.softmax(dim=-1)                       # row-wise → each query sums to 1

        # Weighted sum of values, then merge heads back into one 768-dim vector
        x = (attn @ v).transpose(1, 2).reshape(B, N, C)    # [B, 197, 768]
        x = self.proj(x)                                        # final mix across heads
        return x

vit.py replaces the three explicit lines (q @ kᵀ, softmax, @ v) with F.scaled_dot_product_attention(q, k, v), which computes exactly this (default scale 1/√dk) in one fused kernel and never stores the score matrix.

Key difference from decoder-only LLM: No causal mask. In an LLM, token t can only attend to tokens 0..t; in ViT, token 0 ([CLS]) can attend to token 196 and vice versa. This is why ViT is an encoder, not a decoder.

GPU view: The two matmuls (Q·Kᵀ and attn·V) are batched GEMMs on Tensor Cores. The softmax in between is memory-bound. FlashAttention-style kernels fuse all three and never write the [B, 12, 197, 197] score matrix to DRAM. For ViT-B at 224 px that matrix is modest (12 × 197² × 2 B ≈ 0.93 MB per image per layer at FP16, ≈ 60 MB per layer at batch 64), but it grows as T²: at 1024 px (T = 4097) it is ≈ 403 MB per image per layer.

Feed-Forward Network (MLP) ▼

Purpose: Non-linear transformation applied independently to each token. Attention mixes between tokens; the MLP mixes within each token's embedding.

Why 4× expansion: The hidden layer is 4× wider than the input (768 → 3072 → 768), which gives each token a lot of per-token capacity. The 4× ratio is a convention inherited from the original Transformer and BERT, not a proven optimum: shape-optimized ViTs use other widths (SigLIP's So400m encoder: 1152 → 4304, ≈ 3.7×), and SwiGLU FFNs, as in LLaMA, use ≈ 8/3 × d per projection.

class MLP(nn.Module):
    def __init__(self, in_features, hidden_features=None, out_features=None, drop=0.0):
        super().__init__()
        hidden_features = hidden_features or in_features * 4   # 3072 for ViT-B
        out_features = out_features or in_features
        self.fc1 = nn.Linear(in_features, hidden_features)     # expand: [768 → 3072]
        self.act = nn.GELU()                                   # smooth activation, not ReLU
        self.fc2 = nn.Linear(hidden_features, out_features)    # contract: [3072 → 768]

    def forward(self, x):
        x = self.fc1(x)   # [B, 197, 768] → [B, 197, 3072]
        x = self.act(x)   # element-wise GELU
        x = self.fc2(x)   # [B, 197, 3072] → [B, 197, 768]
        return x

# Block builds it as: MLP(in_features=dim, hidden_features=int(dim * mlp_ratio))

FLOPs per layer: 2 FLOPs/MAC × B × T × (d · d_ff) × 2 matmuls = 2 × 1 × 197 × 768 × 3072 × 2 ≈ 1.86 GFLOPs (0.93 GMACs) for ViT-B at batch 1. Across 12 layers: ≈ 22.3 GFLOPs, about 64% of the model's 35.1 GFLOPs (= 17.6 GMACs) — MLPs, not attention, dominate ViT's FLOP budget.

GPU view: Both linears are pure GEMMs on Tensor Cores. GELU is element-wise and memory-bound; production engines fuse bias + GELU into the fc1 GEMM epilogue (e.g., a cuBLASLt epilogue or TensorRT's automatic fusion) to avoid a round-trip to DRAM.

Classification Head ▼

Purpose: Take the CLS token's final embedding (after L layers of attention and the final LayerNorm) and map it to class logits. The CLS token has aggregated information from every patch by this point — it's the image's global representation.

class ViT(nn.Module):
    def __init__(self, ..., num_classes=1000):
        # ... patch embed, encoder blocks ...
        self.norm = nn.LayerNorm(embed_dim, eps=1e-6)     # eps as in the original ViT / timm / torchvision
        self.head = nn.Linear(embed_dim, num_classes)    # 768 → 1000 (ImageNet)

    def forward(self, x):
        B = x.shape[0]
        x = self.patch_embed(x)                                   # [B, 196, 768]
        x = torch.cat([self.cls_token.expand(B, -1, -1), x], dim=1)  # [B, 197, 768]
        x = x + self.pos_embed                                    # [B, 197, 768]

        for block in self.blocks:
            x = block(x)                     # [B, 197, 768] — shape unchanged

        x = self.norm(x)                     # final LayerNorm before head
        cls_token = x[:, 0]                  # [B, 768] — grab just the CLS slot
        return self.head(cls_token)        # [B, 1000] — class logits

MLP head vs Linear head: the paper pre-trains with an MLP head (one tanh hidden layer) and fine-tunes with a single linear layer; fine-tuned checkpoints and this code use the Linear.

Alternatives: global average pooling over the patch tokens (MAE fine-tuning, "Better plain ViT baselines") or an attention-pooling (MAP) head (SigLIP). Accuracy is on par, so use whichever your checkpoint was trained with. VLMs skip pooling entirely and pass all patch tokens to the LLM — the VLM module drops both [CLS] and the head.

5. ViT vs CNN: When to Use What

Aspect CNN (ResNet, EfficientNet) ViT
Inductive Bias Strong: locality, translation equivariance (weight sharing) Weak: only patching + a shared per-token MLP; the 2D layout is learned from data
Data Efficiency Trains well from scratch on small datasets Original 2020 recipe needed ImageNet-21k (14M) or JFT-300M pre-training; DeiT-style augmentation + distillation trains well on ImageNet-1k (1.3M) alone. In practice: start from a pretrained checkpoint
Scaling Also scales when trained comparably (NFNets match ViTs at JFT-4B scale, Smith et al. 2023) Scales well; dominant at foundation-model scale, helped by shared tooling with LLMs and easy multimodal fusion
Global Context Requires deep networks (large receptive field) From layer 1 (self-attention)
Inference kernels Mature, highly tuned conv kernels (cuDNN, TensorRT) Mostly large GEMMs (Tensor-Core friendly) plus fused attention; cost grows as T² at high resolution
Transfer Learning Good Excellent (especially with large pretraining)
💡 Practical Guidance

Use CNN when: training from scratch on very little data, or targeting tiny MCU/NPU accelerators without good transformer support.

Use ViT when: a pretrained checkpoint exists, you need multimodal features (VLM/VLA), or you want the best accuracy at scale. On Jetson Orin-class GPUs with TensorRT, efficient ViTs run in real time (EfficientViT reports TensorRT FP16 latencies on Jetson AGX Orin), and ViT backbones such as DINOv2 and SigLIP are common in robotics stacks.

Hybrid approaches: ConvNeXt (CNN with transformer tricks), early-conv stems + ViT, EfficientViT (conv + linear attention).

6. GPU Optimization Techniques

In plain words: a ViT forward pass is one big "prefill". Every weight is reused by all ~200 tokens, so the GPU's arithmetic, not its memory bus, sets the speed. Fewer tokens and lower-precision Tensor Cores help most.

The general techniques used below (quantization, kernel fusion, FlashAttention, the roofline model) are explained step by step in the Memory & inference efficiency cookbook.

ViT-Specific Optimizations

Technique Benefit Implementation
Fused attention (FlashAttention-style) Never writes the T×T score matrix to DRAM: O(T) memory instead of O(T²). Small win at 224 px, large at high resolution F.scaled_dot_product_attention; TensorRT fused MHA
Patch embedding as one GEMM Conv2d(k = s = P) is one GEMM-shaped kernel, no separate reshape/copy TensorRT, cuDNN
INT8 quantization Up to 2× Tensor-Core throughput and ½ the weight bytes vs FP16 (Orin's Ampere GPU has no FP8 Tensor Cores) TensorRT INT8 PTQ or explicit Q/DQ (NVIDIA ModelOpt); torchao on GPU. Not torch.ao.quantization eager mode: CPU-only and slated for removal
FP16/BF16 ½ the weight/activation memory of FP32, Tensor-Core matmuls torch.autocast("cuda", dtype=torch.float16), model.half(); TensorRT --fp16
Operator fusion Fewer DRAM round-trips for memory-bound element-wise ops QKV as one GEMM; bias + GELU in the fc1 epilogue; residual-add + LayerNorm; fused MHA (TensorRT does these automatically; dropout is a no-op at inference)
Dynamic resolution Run at a new input size without retraining from scratch Bicubic-interpolate pos_embed (paper §3.2), then rebuild the static TensorRT engine for the new shape
📐 Back-of-envelope: ViT-B/16 on Jetson Orin Nano Super, batch 1, FP16

Rule of thumb: a Linear layer applied to T tokens does 2·T FLOPs per weight, and an FP16 weight is 2 bytes, so its arithmetic intensity is ≈ T FLOP/byte (ignoring activations). ViT-B handles T = 197 tokens per image → ≈ 197 FLOP/byte (whole model: 35.1 GFLOP ÷ 173 MB of weights ≈ 203).

The device's ridge point: NVIDIA lists the Orin Nano Super at 17 FP16 TFLOPS (half its 33 dense INT8 TOPS) and 102 GB/s of LPDDR5 → ridge ≈ 17 000 / 102 ≈ 167 FLOP/byte. Above the ridge you are compute-bound; below it, bandwidth-bound.

Two lower bounds: compute 35.1 GFLOP ÷ 17 TFLOPS ≈ 2.1 ms; weight streaming 86.6 M × 2 B = 173 MB ÷ 102 GB/s ≈ 1.7 ms. So ViT-B is already (slightly) compute-bound at batch 1, and more so at larger batches (batch 4: 8.3 ms of compute vs the same 1.7 ms of weights). Lower-precision Tensor Cores (INT8) buy speed here; memory tricks don't. Real TensorRT latencies are higher than these bounds (kernel efficiency, LayerNorm/softmax/GELU traffic, clocks).

Contrast with Module 1: an LLM in decode processes T = 1 token per step, so intensity ≈ 1 FLOP/byte, about 167× below the ridge (≈ 167 FLOP/byte). That's why KV caches and weight quantization dominate LLM inference, while ViT has no decode phase: the whole image is one "prefill".

⚠️ ViT activation memory is small at 224 px

• Attention scores, per layer: 197 × 197 × 12 heads × 4 B = 1.9 MB per image (FP32).

• FFN hidden activation, per layer: 197 × 3072 × 4 B = 2.4 MB per image — about the same size.

• At inference, activations are freed layer by layer, so the per-layer peak (a few MB per image) is what matters.

• At 1024 px (T = 4097, the resolution of SAM's ViT-H image encoder), the per-layer scores grow to ≈ 806 MB per image in FP32 (403 MB in FP16). That is why fused attention and windowed attention matter at high resolution. For comparison, an LLM prefill of 4096 tokens with 32 heads would need 4096² × 32 × 4 B ≈ 2.1 GB per layer if the scores were materialized.

7. Recap, Self-Check and Exercises

Key takeaways

  • ViT = patch front-end + [CLS] + learned position table + the Module-1 block, with no causal mask and no KV cache.
  • Patch embedding is one GEMM [N, P²C] @ [P²C, d]; Conv2d(k = s = P) is the same math in one kernel. For ViT-B/16, P²C = d = 768 only by coincidence.
  • Attention is order-blind; position embeddings are the only source of "where", and the 2D layout is learned from a 1D table.
  • T = (H/P)² + 1. Per layer ≈ 12·T·d² + 2·T²·d MACs; at 224 px the T² part is ~4%, and the FFN (~64%) dominates.
  • Paper "GFLOPs" are MACs: ViT-B/16 = 17.6 GMACs = 35.1 GFLOPs.
  • Resolution is the big lever: 224 → 1024 px multiplies ViT-B compute by ~38× (T² part 4% → 47% of each layer).
  • At batch 1 FP16 on an Orin Nano Super, ViT-B sits just above the roofline ridge (intensity ≈ T ≈ 200 FLOP/byte): compute-bound, unlike LLM decode.

Self-check

1. How many tokens does ViT-L/14 see at 336×336?

Answer
(336/14)² = 24² = 576 patches, + 1 [CLS] = 577 tokens. This is the CLIP ViT-L/14-336 tower that LLaVA-1.5 uses in the VLM module (where [CLS] is dropped, leaving 576 image tokens).

2. What is the shape of ViT-L/16's patch projection? And ViT-H/14's?

Answer
ViT-L/16: 16·16·3 = 768 inputs → d = 1024 outputs. ViT-H/14: 14·14·3 = 588 → 1280. ViT-B/16's square 768 × 768 is a coincidence.

3. Remove pos_embed and shuffle the patches. What happens to the patch outputs, and to [CLS]?

Answer
The patch outputs come out shuffled the same way (attention and the FFN are permutation-equivariant) and the [CLS] output is unchanged. vit.py's demo_permutation() measures a relative error of ~2e-7 without pos_embed vs ~5e-2 with it.

4. Your checkpoint was trained at 224 px but you deploy at 448 px. What breaks, how do you fix it, and what does it cost?

Answer
T goes from 197 to 785, but pos_embed has 197 rows. Keep row 0 (CLS), reshape the other 196 rows to a 14×14×d grid, bicubic-interpolate to 28×28, flatten and re-attach CLS (the paper's §3.2 recipe), then rebuild the static TensorRT engine. Cost: 78.5 vs 17.6 GMACs ≈ 4.5×, more than the 4× pixel increase because of the T² term.

5. Why does ViT have no KV cache?

Answer
There is no autoregressive loop: all tokens are known up front and processed in one bidirectional pass, so nothing computed for one step is reused by a later step.

6. For ViT-B/16 at 224 px, how big is the T² part relative to the linear layers, and at what T would they be equal?

Answer
Ratio = 2T²d / 12Td² = T/(6d) = 197/4608 ≈ 0.043. Equal at T = 6d = 4608 tokens, i.e. a 68×68 grid ≈ 1088 px at P = 16.

7. A paper table says ViT-B/16 = 17.6 GFLOPs, but vit.py prints 35.1 GFLOPs. Who is wrong?

Answer
Neither. The paper's number is 17.6 G multiply-accumulates; each MAC is 2 FLOPs, so 35.1 GFLOPs. Use the 35.1 figure when dividing by a GPU's peak TFLOPS.

8. Batch 1, FP16, Orin Nano Super (17 TFLOPS, 102 GB/s): is ViT-B/16 compute- or bandwidth-bound?

Answer
Compute bound ≈ 35.1 GFLOP / 17 TFLOPS ≈ 2.1 ms; weight streaming ≈ 173 MB / 102 GB/s ≈ 1.7 ms. Intensity ≈ 203 FLOP/byte vs a ridge of ≈ 167, so it is (slightly) compute-bound, and more so at larger batch. LLM decode (T = 1) is about 167× below the ridge.

9. Derive the per-block parameter count of ViT-B (d = 768, d_ff = 4d) from the layer shapes.

Answer
QKV (3d² + 3d) + out-proj (d² + d) + fc1 (4d² + 4d) + fc2 (4d² + d) + 2 LayerNorms (4d) = 12d² + 13d = 7,077,888 + 9,984 = 7,087,872, exactly what print_model_summary() prints.

10. What does the VLM module remove from this ViT, and why?

Answer
The [CLS] token and the classification head. The LLM wants every patch token (spatial detail), not one pooled vector, and it is not predicting ImageNet classes.

8. Condensed Reference Implementation

An inference-only excerpt of vit.py: no dropout, simplified signatures, no analysis helpers. It is state-dict compatible with vit.py (same parameter names and shapes).

"""
Vision Transformer (ViT) Reference Implementation (condensed, inference-only)
Full version with dropout, FLOP counting and demos: vit.py
"""
import torch
import torch.nn as nn
import torch.nn.functional as F

class PatchEmbed(nn.Module):
    """Convert image to patch embeddings using Conv2d."""
    def __init__(self, img_size=224, patch_size=16, in_chans=3, embed_dim=768):
        super().__init__()
        self.img_size = img_size
        self.patch_size = patch_size
        self.num_patches = (img_size // patch_size) ** 2
        self.proj = nn.Conv2d(in_chans, embed_dim, kernel_size=patch_size, stride=patch_size)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # x: [B, 3, H, W] -> [B, num_patches, embed_dim]
        x = self.proj(x)  # [B, embed_dim, H/P, W/P]
        x = x.flatten(2).transpose(1, 2)  # [B, num_patches, embed_dim]
        return x

class Attention(nn.Module):
    """Multi-head self-attention (no causal mask)."""
    def __init__(self, dim=768, num_heads=12, qkv_bias=True):
        super().__init__()
        assert dim % num_heads == 0
        self.num_heads = num_heads
        self.head_dim = dim // num_heads
        self.qkv = nn.Linear(dim, dim * 3, bias=qkv_bias)
        self.proj = nn.Linear(dim, dim)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B, N, C = x.shape  # [B, T, d]: batch, tokens T, width d (timm names them N, C)
        qkv = self.qkv(x).reshape(B, N, 3, self.num_heads, self.head_dim).permute(2, 0, 3, 1, 4)
        q, k, v = qkv.unbind(0)

        # softmax(q @ k^T / sqrt(d_k)) @ v in one fused kernel (PyTorch 2.0+)
        x = F.scaled_dot_product_attention(q, k, v)  # [B, h, T, d_k]
        x = x.transpose(1, 2).reshape(B, N, C)
        return self.proj(x)

class MLP(nn.Module):
    """Feed-forward network with GELU activation."""
    def __init__(self, dim=768, mlp_ratio=4.0):
        super().__init__()
        hidden = int(dim * mlp_ratio)
        self.fc1 = nn.Linear(dim, hidden)
        self.fc2 = nn.Linear(hidden, dim)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.fc2(F.gelu(self.fc1(x)))

class Block(nn.Module):
    """Transformer encoder block with pre-norm."""
    def __init__(self, dim=768, num_heads=12, mlp_ratio=4.0):
        super().__init__()
        self.norm1 = nn.LayerNorm(dim, eps=1e-6)
        self.attn = Attention(dim, num_heads)
        self.norm2 = nn.LayerNorm(dim, eps=1e-6)
        self.mlp = MLP(dim, mlp_ratio)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = x + self.attn(self.norm1(x))  # Pre-norm + residual
        x = x + self.mlp(self.norm2(x))
        return x

class ViT(nn.Module):
    """Vision Transformer for image classification."""
    def __init__(
        self,
        img_size=224,
        patch_size=16,
        in_chans=3,
        num_classes=1000,
        embed_dim=768,
        depth=12,
        num_heads=12,
        mlp_ratio=4.0,
    ):
        super().__init__()
        self.patch_embed = PatchEmbed(img_size, patch_size, in_chans, embed_dim)
        num_patches = self.patch_embed.num_patches

        self.cls_token = nn.Parameter(torch.zeros(1, 1, embed_dim))
        self.pos_embed = nn.Parameter(torch.zeros(1, num_patches + 1, embed_dim))

        self.blocks = nn.ModuleList([
            Block(embed_dim, num_heads, mlp_ratio) for _ in range(depth)
        ])
        self.norm = nn.LayerNorm(embed_dim, eps=1e-6)
        self.head = nn.Linear(embed_dim, num_classes)

        # Only matters when training from scratch (vit.py also inits the Linears)
        nn.init.trunc_normal_(self.pos_embed, std=0.02)
        nn.init.trunc_normal_(self.cls_token, std=0.02)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B = x.shape[0]
        x = self.patch_embed(x)  # [B, 196, 768]

        cls_tokens = self.cls_token.expand(B, -1, -1)
        x = torch.cat([cls_tokens, x], dim=1)  # [B, 197, 768]
        x = x + self.pos_embed

        for block in self.blocks:
            x = block(x)

        x = self.norm(x)
        return self.head(x[:, 0])  # [B, num_classes]

# Model configurations
def vit_base_patch16():
    return ViT(patch_size=16, embed_dim=768, depth=12, num_heads=12)

def vit_large_patch16():
    return ViT(patch_size=16, embed_dim=1024, depth=24, num_heads=16)

def vit_huge_patch14():
    return ViT(patch_size=14, embed_dim=1280, depth=32, num_heads=16)

if __name__ == "__main__":
    model = vit_base_patch16().eval()
    print(f"ViT-B/16 Parameters: {sum(p.numel() for p in model.parameters()):,}")  # 86,567,656

    x = torch.randn(1, 3, 224, 224)
    with torch.no_grad():
        out = model(x)
    print(f"Input: {x.shape} -> Output: {out.shape}")
